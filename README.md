# 달빛 포션 상점

초등학교 5학년 2학기 **「소수의 곱셈」** 을 반복 연습하는 2D 웹게임입니다.
밤에만 여는 포션 가게의 주인이 되어 손님의 주문을 받고, 서랍의 약초를 직접 항아리에 넣고, 몇 g을 넣을지 계산해 포션을 만듭니다.
계산한 값이 곧 솥에 들어가는 재료량이고, 정확하게 계량할수록 포션이 선명해지고 손님이 만족합니다.

- 학생이 혼자 접속해서 바로 하는 게임입니다. 교사 설정·학급 관리·순위·학습 범위 고르기는 없습니다. 학습 유형은 영업할수록 게임이 자동으로 소개합니다.
- 시간제한·손님 인내심 감소·재료비·임대료는 없습니다. 힌트와 ‘네?’(다시 설명)를 써도 판매금이 줄지 않습니다. 잘못 만든 포션을 전달하면 판매금 대신 손님에게 **보상금**(정상가 ÷ 3)을 주고, 소지금이 **−50G 이하**가 되면 영업이 중단되어 전날 영업 시작부터 다시 합니다.
- 서버·로그인·유료 API 없이 브라우저만으로 동작합니다. 진행 상황은 브라우저(localStorage)에 저장됩니다.
- 태블릿·모바일(터치·화면 키패드)과 노트북·PC(마우스·키보드) 모두 지원합니다. 모든 장면은 기준 무대(1280×720) 하나를 **같은 배율로 통째로** 줄이고 키우므로 기기마다 배치가 달라지지 않습니다.

> **최신 변경 (오프닝·보상금·전날 복구판, v0.10.0)**: 잘못 만든 포션은 판매금 0G에 **피해 보상금(정상 판매가 총액 ÷ 3, 반올림)** 을 전달하는 순간 한 번 냅니다. 소지금은 음수가 될 수 있고 **−50G 이하**가 되면 ‘영업 중단’ 화면이 나오며 **전날 영업 시작 상태**로 되돌려 다시 할 수 있습니다(영업일마다 시작 상태를 복구 지점으로 저장). 새 게임에는 타이틀 그림이 상점 쪽으로 다가가며 주인공 대사 세 줄이 나오는 **오프닝**이 생겼고, 창구 손님의 대기 움직임(숨쉬기·좌우 흔들림)이 조금 더 눈에 띕니다. 저장 버전 9. 자세한 내용은 [`docs/OPENING_REFUND_RETRY_REPORT.md`](docs/OPENING_REFUND_RETRY_REPORT.md).
>
> 이전 변경 (주문 대사·자동 가마솥판, v0.9.0): 문제은행을 **주문 대사 개선판 TXT**(`docs/question-bank/Moonlight-Potion-Shop-180-Questions-Revised.txt`)로 바꿔, 손님 주문에 포션·병 수·지정 재료와 양·조건(병당/기준의 배수, 이 재료만)이 모두 들어가고 “몇 g?” 같은 계산 질문으로 끝나지 않습니다(180문항 ID·수치·정답은 그대로). 생성 주문 템플릿·‘네?’·기다리는 말도 포션과 수량을 함께 말하게 했습니다. **마녀의 자동 솥**은 이제 끄는 스위치 없이, 가지고만 있으면 **재료를 모두 넣는 순간 포션이 바로 완성**(젓기·병 담기 생략)되고, 전달은 창구에서 직접 합니다. 저장 버전 8. 자세한 내용은 [`docs/DIALOGUE_AUTOCAULDRON_REPORT.md`](docs/DIALOGUE_AUTOCAULDRON_REPORT.md).
>
> 이전 변경 (문제은행·타이틀·튜토리얼판, v0.8.0): 문제은행 180문항(하·중·상 × 소수×자연수·자연수×소수·소수×소수)을 주 출제원으로 쓰고, 타이틀 그림과 **새로 시작하기·이어하기**, 새 게임 **첫 주문 튜토리얼**, 위쪽 띠 없는 간소한 제작대, 기기별 같은 배율 화면을 넣었습니다. 자세한 내용은 [`docs/QUESTIONBANK_TITLE_RESPONSIVE_REPORT.md`](docs/QUESTIONBANK_TITLE_RESPONSIVE_REPORT.md).
>
> 이전 변경 (UI 간소화·서랍 구매판): 레시피북은 1병당 재료만 크게, 계산식 힌트는 주문서 팝업의 **힌트** 버튼으로 옮겼고(오답 뒤 해설은 그대로), 마감 화면은 네 가지 결과만, 창구 주문 요약은 두 줄만 보여 줍니다. 제작대 위쪽 서랍에서 **깃털풀·바람 정령의 파편**을 사서 해금하면 **바람 걸음 포션**이 열리고 다음 영업부터 주문이 들어옵니다. 자세한 내용은 [`docs/UI_UNLOCKS_REPORT.md`](docs/UI_UNLOCKS_REPORT.md).
>
> 이전 변경 (제작대·기력 포션판): 창구·제작대 PNG를 자르지 않고 전체가 보이게 표시하고, 탑뷰 제작대(서랍·항아리·병 받침 PNG)와 책 모양 레시피·주문서 팝업을 넣었습니다. 새 주문은 **기력초 한 가지로 만드는 기력 포션**만 나옵니다. 돈으로 재료를 해금하고 필요한 재료가 모두 있으면 레시피가 열리는 구조를 마련했습니다(지금은 기력초가 처음부터 해금). 자세한 내용은 [`docs/WORKBENCH_ENERGY_REPORT.md`](docs/WORKBENCH_ENERGY_REPORT.md).
>
> 4단계(시각적 완성도): 가게·창구·제조대 배경과 손님 4종(표정 5가지)·재료 그릇·포션 4종을 새로 그렸고, 손님 등장·퇴장, 재료 붓기, 젓기, 완성 빛, 병 담기, 판매 반응 연출과 효과음(켜기·끄기·음량)을 넣었습니다. **젓기 버튼을 없애고** 막대를 직접 잡고 움직여 젓습니다.
> 3단계의 게임 규칙(하루 손님 5명, 주문·‘네?’, 정확한 소수 계산, 힌트, 오답 해설과 오답 제조, 품질별 판매금, 유형 소개, 학습 기록·복습, 저장·이어하기·내보내기·가져오기, 덧문)은 그대로입니다.

## 1. 로컬에서 설치하고 실행하기

**준비물:** [Node.js](https://nodejs.org/ko) 22 LTS(22.18 이상) 또는 24 이상. 설치 후 터미널에서 `node -v`로 확인하세요.

```bash
# 프로젝트 폴더에서
npm install        # 처음 한 번 (package-lock.json이 생깁니다)
npm run dev        # 개발 서버 실행 → 터미널에 나온 주소(보통 http://localhost:5173)를 브라우저로 엽니다
```

그 밖의 명령:

| 명령 | 하는 일 |
|---|---|
| `npm test` | 계산·판정·게임 규칙 자동 테스트 (Node 내장 테스트 실행기) |
| `npm run typecheck` | TypeScript 타입 검사 |
| `npm run build` | 타입 검사 후 배포용 파일을 `dist/` 폴더에 만듭니다 |
| `npm run preview` | 만든 `dist/`를 로컬에서 미리 보기 |

> **package-lock.json 안내:** 이 ZIP은 패키지 저장소(npm)에 접근할 수 없는 환경에서 만들어져 `package-lock.json`이 들어 있지 않습니다(기준 ZIP에도 없었음).
> 처음 `npm install`을 하면 자동으로 생기니, 그 파일도 함께 저장소에 올려 두면 이후 배포에서 같은 버전이 설치됩니다(`npm ci`).
> 올리지 않아도 배포 workflow가 `npm install`로 설치하므로 배포는 됩니다.

## 2. ZIP을 풀어 GitHub 저장소에 올리기

1. GitHub에서 새 저장소를 만듭니다. (예: `moonlight-potion-shop`, Public 권장 — 무료 계정은 Public 저장소에서 Pages를 쓸 수 있습니다)
2. `Moonlight-Potion-Shop-phase1.zip`의 압축을 풉니다. 압축을 풀면 `Moonlight-Potion-Shop` 폴더가 생깁니다.
3. **그 폴더의 안쪽 내용**(`package.json`, `index.html`, `src/`, `public/`, `.github/` 등)이 저장소의 **맨 위(루트)** 에 오도록 올립니다.
   `Moonlight-Potion-Shop` 폴더 자체를 한 단계 더 넣어 올리면 배포가 되지 않습니다.
   - **Git 사용 시:** 압축을 푼 폴더 안에서
     ```bash
     git init
     git add .
     git commit -m "달빛 포션 상점 1단계"
     git branch -M main
     git remote add origin https://github.com/<사용자이름>/<저장소이름>.git
     git push -u origin main
     ```
   - **웹 업로드 시:** 저장소 화면의 **Add file → Upload files**에 폴더 안의 파일과 폴더를 끌어다 놓고 **Commit changes**를 누릅니다.
     ⚠️ `.github`처럼 점(.)으로 시작하는 폴더는 컴퓨터에서 숨김 폴더라 빠지기 쉽습니다. 다음 항목으로 꼭 확인하세요.

## 3. `.github/workflows/deploy.yml`이 올라갔는지 확인하기

- 저장소 첫 화면의 파일 목록에 `.github` 폴더가 보여야 하고, 들어가면 `workflows/deploy.yml`이 있어야 합니다.
- 주소창에 `https://github.com/<사용자이름>/<저장소이름>/blob/main/.github/workflows/deploy.yml`을 입력해 열리는지 확인해도 됩니다.
- 없다면: 저장소에서 **Add file → Create new file**을 누르고 파일 이름 칸에 `.github/workflows/deploy.yml`을 입력한 뒤, ZIP 안의 같은 파일 내용을 붙여 넣고 커밋합니다.
  (Windows 탐색기: 보기 → 표시 → 숨긴 항목 / macOS Finder: `Cmd + Shift + .` 로 숨김 폴더를 볼 수 있습니다.)

## 4. Settings → Pages에서 Source를 GitHub Actions로 선택하기

1. 저장소 상단의 **Settings** → 왼쪽 메뉴 **Pages**로 갑니다.
2. **Build and deployment → Source**에서 **GitHub Actions**를 선택합니다. (저장할 버튼은 따로 없고 선택하면 바로 적용됩니다.)

## 5. 배포 완료 확인과 사이트 접속

1. 저장소 상단 **Actions** 탭에서 **Deploy to GitHub Pages** 실행을 엽니다.
   - Source를 GitHub Actions로 바꾸기 전에 push했다면 첫 실행이 실패했을 수 있습니다. 왼쪽에서 **Deploy to GitHub Pages** → 오른쪽 **Run workflow** → **Run workflow**를 눌러 다시 실행합니다.
2. `build`와 `deploy` 두 작업이 모두 초록색 ✓ 이 되면 배포 완료입니다(보통 1~3분).
3. `deploy` 작업 안이나 **Settings → Pages** 상단에 나온 주소로 접속합니다.
   주소 형식: `https://<사용자이름>.github.io/<저장소이름>/`
4. 이후에는 `main` 브랜치에 push할 때마다 자동으로 다시 배포됩니다.

### 이미 배포한 저장소를 4단계로 업데이트하기

저장소(예: `MoonlightPotionShop-5-2-4`)의 설정과 workflow는 바꿀 필요가 없습니다(`.github/workflows/deploy.yml`, `vite.config.ts`는 3단계와 똑같습니다). 파일만 바꾸면 됩니다.

1. `Moonlight-Potion-Shop-phase4.zip`을 풀고, 폴더 **안쪽** 내용을 저장소 루트에 덮어써서 올립니다(웹 업로드: Add file → Upload files에 모두 끌어다 놓기). 새 폴더(`src/audio/`, `public/assets/shop/`)도 함께 끌어다 놓으면 됩니다.
2. **4단계에서 지워야 하는 파일은 없습니다.** (3단계에서 안내한 `src/components/art/FoxArt.tsx`를 아직 지우지 않았다면 그 파일만 지워 주세요.)
3. 새로 생기는 파일·바뀌는 파일 목록은 `docs/PHASE4_REPORT.md`의 ‘GitHub 업데이트 안내’에 있습니다.
4. `main`에 올리면 Actions가 자동으로 다시 배포합니다.
5. 학생들이 쓰던 3단계 저장은 그대로 이어집니다(저장 형식 변경 없음). 2단계·1단계 저장도 처음 열 때 자동으로 옮겨집니다(아래 ‘이전 저장 옮기기’).

### PNG 창구·손님 적용판으로 업데이트하기 (`Moonlight-Potion-Shop-phase4-png.zip`)

1. ZIP 안쪽 내용을 저장소 루트에 덮어써서 올립니다. 새 폴더 `public/assets/npc/`(손님 PNG 15장)와 `public/assets/shop/counter/`(창구 PNG 3장)도 함께 올립니다.
2. **직접 지울 파일: `src/components/art/NightBackdrop.tsx`** (예전 SVG 창구 배경. 더 이상 쓰지 않음. 남아 있어도 빌드는 됩니다)
3. workflow·Pages 설정은 그대로 둡니다. 자세한 변경 목록은 `docs/PNG_COUNTER_REPORT.md`에 있습니다.

### 제작대·기력 포션판으로 업데이트하기 (`Moonlight-Potion-Shop-workbench-energy.zip`)

1. ZIP 안쪽 내용을 저장소 루트에 덮어써서 올립니다. 새 폴더 `public/assets/shop/workbench/`(제작대·책·주문서·책 패널 PNG 4장)도 함께 올립니다.

### 배포 방식 설명 (저장소 이름과 base 경로)

GitHub Pages 사이트는 `/<저장소이름>/` 하위 경로에서 열립니다. workflow가 저장소 이름을 읽어
`VITE_BASE_PATH=/<저장소이름>/` 환경 변수를 만들고, `vite.config.ts`의 `base`가 이 값을 사용합니다.
그래서 저장소 이름을 무엇으로 정하든 코드를 고칠 필요가 없습니다.

- 이미지·효과음은 `src/lib/assets.ts`의 `assetUrl()`로 경로를 만들어 base 경로가 자동으로 붙습니다.
- 화면 전환은 주소(URL)가 아니라 게임 상태로 하므로, 어느 화면에서 새로고침해도 404가 나지 않습니다.
- 저장소 이름이 `<사용자이름>.github.io`이면 루트(`/`)로 빌드합니다.
- 사용자 지정 도메인을 연결했다면 workflow의 `Set base path` 단계에서 `BASE_PATH="/"`로 바꾸세요.

## 게임 방법

**타이틀**: 접속하거나 새로고침하면 늘 타이틀부터 열립니다(이것만으로는 저장이 바뀌지 않음).
- **새로 시작하기**: 진행이 있으면 “처음부터 새로 시작할까요?” 확인 → **취소**하면 그대로, **지우고 새로 시작**하면 일차·달빛 동전·산 재료와 상품·학습 기록을 처음으로 하고 **오프닝** → 첫 주문 튜토리얼로 시작합니다(소리 설정은 유지).
- **이어하기**: 저장된 화면(손님 주문·계량 중 입력값·넣은 재료·젓기 정도·전달 전후·영업 마감)으로 돌아갑니다. 이미 받은 판매금이나 마친 행동은 다시 하지 않습니다. 저장이 없으면 누를 수 없습니다.
- 왼쪽 아래 작은 버튼: **학습 기록**, **저장·기록 관리**(내보내기·가져오기), **소리**.

**오프닝** (새로 시작한 게임에만): 타이틀 그림을 그대로 두고 버튼만 숨긴 채, 그림이 상점 문 쪽으로 천천히 1.12배까지 확대되어 멈춥니다. 확대가 시작되면 아래쪽 대화창에 주인공의 말이 한 줄씩 나옵니다.
“드디어 열었어! 나만의 포션 상점이야!” → “포션의 달인이셨던 우리 할머니를 본받아서, 세계 최고의 포션을 만들겠어!” → “내 포션들로 손님들을 기쁘게 해 줘야지!”
**다음** 버튼이나 화면 빈 곳을 눌러야 넘어가고(한 번에 한 대사, 자동으로 넘기지 않음), 마지막 대사를 넘기면 창구로 바뀌어 덧문이 열리고 → 첫 손님이 나타나고 → 첫 주문 튜토리얼이 시작됩니다. 오프닝 도중 새로고침하면 ‘이어하기’로 보던 대사부터 이어지고, 끝낸 오프닝은 다시 나오지 않습니다(이어하기·전날 복구 포함). 이전 저장에는 나오지 않습니다.

**첫 주문 튜토리얼** (새로 시작한 게임의 첫 손님, 여우의 기력 포션 2병): 소개 카드 확인 → ‘오케이’로 주문 받기 → 주문서 열고 닫기 → 레시피북 열고 닫기 → 기력초를 항아리에 놓기(눌러 집고 항아리 누르기 또는 끌어다 놓기) → 필요한 양 계산해 입력·제출 → 이 양으로 투입 → 막대로 젓기 → 병에 담기 → 창구로 가져가기 → 전달하기. 실제 화면 요소에 금빛 테두리와 한두 문장 안내가 붙고, **그 행동을 해야** 다음으로 넘어갑니다(시간으로 넘어가지 않음). 정답은 미리 알려 주지 않고, 틀려도 해설을 본 뒤 그대로 완성합니다. **안내 건너뛰기**를 누르면 주문은 그대로 두고 안내만 끝납니다. 튜토리얼로 돈을 더 주지 않습니다. 단계는 저장되어 새로고침·이어하기 뒤 그 자리부터 다시 안내합니다. 이전 저장에는 시작하지 않습니다.

**상시 화면 UI**: 창구·마감 화면은 그림 안쪽 위 가장자리에 **처음 화면 · 밤 N일차 · 손님 n/5 · 음소거 · 달빛 동전 · 상점**. 제작대는 위쪽 띠 없이 아래쪽 빈 나무판 위에 **처음 화면 · 소리(왼쪽) / 달빛 동전 · 창구 보기(오른쪽)** 넷만 둡니다(서랍·책·주문서를 가리지 않음). 상점은 창구·마감 화면에서 엽니다. 젓기 진행 막대·‘병에 담기’·계량 패널처럼 필요한 순간의 버튼은 그때만 나옵니다.

1. **새로 시작하기**(또는 이어하기) → 덧문이 열리고 손님이 옵니다. 그날 처음 나오는 계산 유형이 있으면 소개 카드가 먼저 나옵니다.
2. 손님 주문을 듣고 **오케이 →** 를 누르면 제작대로 갑니다. 무슨 말인지 모르겠으면 **네?** 를 누르세요. 같은 주문을 쉬운 말로 다시 설명해 줍니다(주문 숫자·조건·판매금은 바뀌지 않음).
3. 제작대(위에서 내려다본 작업대)
   - 왼쪽 아래 **레시피** 책: 고른 레시피의 이름과 **1병당 재료**(재료 그림·이름·양)만 크게 보여 줍니다. 오른쪽 면에서 다른 레시피를 고를 수 있고, 잠긴 레시피는 잠김과 필요한 재료만 보입니다.
   - 오른쪽 아래 **주문서**: 왼쪽 면에 손님이 한 원래 말과 ‘네?’ 쉬운 설명, 오른쪽 면에 **힌트** 버튼. 힌트를 누르면 재료마다 필요한 식만 보여 줍니다(예: “기력초: 0.6 × 3을 계산해 보세요.” 계산 결과·정답은 없음). 힌트를 봐도 판매금은 줄지 않습니다.
   - 책 창은 닫기·`Esc`·책 바깥 누르기로 닫습니다. 계량·젓기 중에 열어도 입력 중인 답과 진행은 그대로입니다.
   - 위쪽 서랍의 재료를 눌러 집고 항아리를 누르거나, 항아리로 끌어다 놓습니다(터치도 같음). 항아리 밖에 놓으면 아무 일도 일어나지 않고, 이번 주문에 필요 없는 재료는 넣지 않고 짧게 알려 줍니다(오답·감액 아님). 서랍의 재료는 줄어들지 않습니다.
   - **잠긴 서랍**(자물쇠·가격·잠금 해제 표시)을 누르면 달빛 동전으로 그 재료를 해금합니다. 계량·끌기·젓기 중에는 살 수 없습니다.
   - 키보드: `Tab`으로 서랍 → `Enter`(집기) → `Tab`으로 항아리 → `Enter`(놓기), `Esc` 집기 취소
4. 항아리에 놓으면 **계량 문제**가 열립니다(아직 투입 전). “기력초는 몇 g 넣을까요?”에 답을 입력하고 **제출하기**. 계산식은 처음엔 보이지 않고, 레시피·주문서를 보고 생각합니다. 식이 궁금하면 주문서의 **힌트**를 누릅니다.
5. 제출한 답은 확정됩니다(다시 고쳐 내기 없음). 잘못된 형식(예: `1.`)은 확정하지 않고 다시 입력하게 합니다.
   - 정확하면 ✓ 표시와 **이 양으로 투입하기**
   - 다르면 입력한 양이 빨간색으로 남고, 키패드 자리에 **계산 과정 해설**이 나옵니다. **이 양으로 투입하기**를 누르면 입력한 양 그대로 항아리에 들어갑니다. 비슷한 문제가 다음 영업에 **복습**으로 다른 숫자로 나옵니다.
6. 재료를 모두 넣으면 **젓기**(바람 걸음 포션은 두 재료를 모두 넣어야 저을 수 있음, 넣는 순서는 자유): “막대를 잡고 움직여 포션을 저어 주세요.” 항아리(막대)를 마우스로 누른 채 또는 손가락으로 댄 채 움직입니다. 젓기 버튼은 없습니다.
   - 움직인 거리만큼 진행 막대가 차고, 100%가 되면 물약이 반짝이며 **병에 담기**가 나옵니다. 가만히 누르기·클릭만으로는 진행되지 않습니다.
   - 손을 떼도 진행은 남고, 다시 잡으면 이어서 젓습니다. 새로고침해도 진행 정도가 그대로입니다. 손가락 두 개를 대면 먼저 잡은 손가락만 셉니다.
   - 키보드: `Tab`으로 항아리에 초점 → `←` `→`를 번갈아 누르기
7. **병에 담기**(병 받침에 병이 놓임) → **창구로 가져가기** → **포션 전달하기**. 손님은 포션에 반응하고 판매금을 줍니다. 잘못 만든 포션이면 판매금 없이 손님에게 보상금을 드립니다(창구에 `보상금 −8G`처럼 표시).
8. 손님 5명이 끝나면 **영업 마감** → 덧문이 닫히고 오늘의 결과(오늘 수입·응대한 손님·현재 소지금·잘못 만든 포션) → **다음 날 영업** 또는 **타이틀로**.

- 모든 재료량은 g, 레시피 안에서 같은 양이 없고 전체 레시피에서도 되풀이하지 않습니다(소수 한 자리·두 자리 섞음). 3재료 주문은 하루 최대 2건입니다.

- 물(기본 용액)은 자동으로 들어가며 계량하지 않고 레시피북에도 표시하지 않습니다. 기본 레시피 주문은 정해진 양을 바꾸지 않습니다.
- 바람 걸음 포션 여러 병 주문은 ①(0.4 × 병 수)과 ②(0.35 × 병 수) 두 문제, 맞춤 배수 주문은 ⑤⑥ 두 문제입니다.
- 다른 인수 모양(0.25 × 3, 4 × 0.5 등)은 **손님 지정량 주문**으로 냅니다. 손님이 레시피 대신 “1병에 기력초 0.25g씩” 또는 “우리 집 비법은 4g, 그 0.5배”처럼 양을 정해 줍니다. 원래 대사·쉬운 설명·주문서·힌트·해설이 모두 같은 조건을 씁니다.

| 주문 | 예 | 학습 유형 | 정상 판매금 |
|---|---|---|---|
| 여러 병 | “기력 포션 3병 주세요.” → 0.6 × 3 | ① | 5 × 병 수 |
| 맞춤 배수 | “기력 포션 1병, 기본 레시피의 0.4배로” → 0.6 × 0.4 | ⑤ | 20 |
| 손님 지정량 (1병당 양, 기력 포션) | “1병에 기력초 0.25g씩, 3병” → 0.25 × 3 | ② | 5 × 병 수 |
| 손님 지정량 (기준 양의 배수) | “비법은 기력초 4g, 그 0.5배” → 4 × 0.5 / 4 × 0.25 / 0.35 × 0.4 | ③ ④ ⑥ | 20 |
| 생활 소재 특별 주문 (하루 최대 1건) | “리본 3m의 0.4배와 같은 숫자만큼 기력초를” → 3 × 0.4 (단위 변환이 아님) | ①~⑥ | 20 |
| 곱의 변화 비교 (⑦) | “지난번 2.4 × 3 = 7.2g, 이번 0.24 × 3g → 몇 배?” → 고르기, 양은 자동 계량 | ⑦ | 20 |

**판매금과 피해 보상금** (병에 담을 때 정하고, 돈은 창구에서 **전달하는 순간 한 번만** 움직임)

| 결과 | 손님 반응 | 받는 돈 |
|---|---|---|
| 모든 재료 정확 (올바르게 만든 포션) | 만족 | 정상 판매금 전액 |
| 재료를 하나라도 잘못 계량 (잘못 만든 포션) | 대체로 만족 · 조금 아쉬움 · 불만족 (틀린 개수에 따라) | 판매금 **0G**, 손님에게 **보상금 = 정상 판매가 총액 ÷ 3** (소수 부분 반올림) |

- 보상금은 **주문 단위로 한 번**입니다. 병 수나 틀린 재료 수를 다시 곱하지 않습니다. 예: 정상가 21G → 7G, 24G → 8G, 30G → 10G, 10G → 3G (상한·하한 없음).
- 잘못 만든 포션의 판단은 기존 품질 판정을 그대로 씁니다(비교 문제 ⑦은 고른 답의 정오). 힌트·‘네?’·숫자 입력 형식 오류는 상관없고, 아직 전달하지 않은 주문에는 아무것도 빼지 않습니다.
- 틀려도 해설을 본 뒤 그대로 넣고 완성·전달합니다. 마녀의 자동 솥으로 만들어도 결과와 보상금은 같습니다.
- 연속 클릭·새로고침·이어하기로 같은 주문의 판매금·보상금이 두 번 처리되지 않습니다. 업데이트 전에 이미 전달(정산)한 주문은 그때 받은 금액 그대로이며 다시 계산하지 않습니다.

**영업 중단과 전날 복구**

- 소지금은 보상금 때문에 음수가 될 수 있습니다(상점·서랍 구매는 이전처럼 잔액이 가격보다 적으면 안 됨).
- 전달 직후 소지금이 **−50G 이하**(정확히 −50G 포함, 예: −47G에서 8G를 내 −55G)면 **영업 중단** 화면이 나오고 다음 손님·마감·다음 영업으로 넘어가지 않습니다. −49G까지는 영업을 계속합니다. 중단 화면에서 새로고침해도 중단 상태가 유지됩니다.
- **전날부터 다시 시작**: 영업일마다 시작 상태(소지금·재료 해금·상점 구매·장착·그날 주문 목록·학습 기록·복습·영업 기록)를 복구 지점으로 저장해 두고(오늘·전날 두 개만), 5일차에 중단되면 **4일차 영업 시작 상태**로 되돌립니다. 그 뒤의 판매·구매·보상금·기록은 함께 없던 일이 되어 중복 지급·중복 집계가 없습니다.
- 1일차에 중단되었거나 업데이트 전 저장이라 전날 복구 지점이 없으면 **그날 영업 시작 상태**로 되돌리고, 버튼과 안내에 실제 복구 일차를 적습니다. 복구 지점이 아예 없는 이전 저장은 지우지 않고 ‘저장·기록 관리’의 가져오기를 안내합니다.
- 복구할 때 오프닝은 다시 나오지 않고, 이미 끝낸 튜토리얼도 다시 시작하지 않습니다.

### 문제은행 (주 출제원)

- 원본: `docs/question-bank/Moonlight-Potion-Shop-180-Questions-Revised.txt`(주문 대사 개선판) → `node scripts/convert-question-bank.ts`로 `src/data/questionBank.ts`를 만듭니다(`--check`는 검사만). 정답은 변환할 때 문자열 십진 연산으로 다시 계산해 확인합니다(불일치 0건). 변환기는 직전 데이터와 ID·난이도·유형·포션·재료·인수·정답·병 수가 같은지, 주문 대사 규칙(아래)을 지키는지도 검사합니다. 변환 결과·바로잡은 조사 목록은 [`docs/question-bank/CONVERSION_REPORT.md`](docs/question-bank/CONVERSION_REPORT.md).
- 문항 하나 = **재료 하나의 계산 과제**(손님 지정량 특별 주문). 레시피 기본량은 바꾸지 않습니다.
  - 소수×자연수(여러 병): 지정 재료는 손님이 정한 1병당 양 × 병 수, 나머지 재료는 레시피 1병당 양 × 병 수(함께 계산).
  - 자연수×소수·소수×소수(한 병의 배수): 지정 재료만 손님이 알려 준 기준량 × 배수, 나머지 재료는 레시피 1병 기본량 그대로. 주문서에 ‘특별 조건’과 ‘기본 조건’을 나눠 적습니다.
  - 모든 재료를 계량·투입해야 완성됩니다. 손님 대사는 문항의 `question`, ‘네?’는 `clarification`, 주문서 힌트는 `hint`(식만), 오답 뒤 계량 패널 해설은 `explanation`(①~④)을 문항 ID로 읽습니다.
- 출제: 레시피의 **모든** 재료를 해금했고 학습 유형이 소개된 문항만. 난이도 비율 1~5일차 하 100% / 6~10일차 하 70·중 30 / 11~20일차 하 30·중 60·상 10 / 21일차부터 하 20·중 50·상 30(그 난이도 후보가 없으면 같은 기간에 허용된 다른 난이도). 안 낸 문항부터, 다 내면 가장 오래전에 낸 문항부터 냅니다(같은 날 같은 문항·같은 식 피함).
- 후보가 없을 때(주로 1~3일차, 기력 포션 문항이 적음)만 기존 문제 생성기가 그 자리를 채웁니다. 복습·생활 소재·비교(⑦) 주문과 튜토리얼 첫 주문은 기존 방식입니다.
- 판매가: 여러 병은 1병 판매가 × 병 수(9병 값까지, 24병 같은 대량 주문은 할인), 한 병 배수는 특별 주문 판매가.
- 진행 중이던 날의 주문은 그대로 마치고, 문제은행은 다음 영업부터 쓰입니다.

### 주문 대사 규칙

- 손님 주문(원래 대사)에는 **포션 이름·병 수(또는 한 병)·지정 재료와 양·조건**(1병당 ○g씩인지, 기준량의 ○배인지)이 모두 들어갑니다. 배수 주문은 **그 재료만** 바뀌는지(문제은행), **모든 재료**가 바뀌는지(맞춤 배수 주문)를 밝힙니다.
- “몇 g인가요?”·“총량은?”·“전체 양은?” 같은 계산 질문으로 끝나지 않습니다. 식·정답은 대사와 ‘네?’에 없고, 식은 주문서의 **힌트**에만, 풀이 단계와 정답은 **오답 뒤 해설**에만 나옵니다.
- ‘네?’(쉽게 다시 말하면)는 같은 조건(포션·병 수·양·배수)을 다시 말합니다. 인사·기다림 같은 분위기 말은 주문을 대신하지 않고, 제작 중 창구를 보면 기다리는 말과 함께 “기력 포션 2병, 잘 부탁하오.”처럼 포션과 수량을 다시 말합니다.
- 포션·재료 이름과 숫자 뒤 조사(은/는·이/가·을/를)는 받침에 맞게 씁니다.

### 학습 유형과 자동 소개

| 유형 | 처음 나오는 때 |
|---|---|
| ① 소수 한 자리 × 자연수, ② 소수 두 자리 × 자연수 | 첫 영업 |
| ③ 자연수 × 소수 한 자리, ④ 자연수 × 소수 두 자리 | 영업을 1번 마친 다음 날 |
| ⑤ 소수 한 자리 × 소수 한 자리, ⑥ 소수 두 자리 × 소수 한 자리 | 영업을 2번 마친 다음 날 |
| ⑦ 곱의 소수점 위치 변화(10배·같음·1/10배 고르기) | 영업을 3번 마친 다음 날 |

- 소개는 영업을 마칠 때마다 한 단계씩 진행합니다. 정답률이나 힌트 사용으로 막지 않습니다.
- 소개된 유형 안에서만 출제하고, 처음 나오는 유형은 그날 꼭 등장합니다.
- 기본 수의 범위: 자연수 2~9, 소수 한 자리 0.2~2.5, 소수 두 자리 0.12~1.25 (예외: 초콜릿 14.35 × 10, 비교 문제의 10배·1/10배로 바뀐 수)
- 레시피(1병당): 기력 포션 기력초 0.6g, 바람 걸음 포션 깃털풀 0.4g + 바람 정령의 파편 0.35g. 문제를 만들려고 기본량을 바꾸지 않습니다. (이전 버전 레시피 별빛·용기·새싹·안개는 저장 호환용으로만 남아 있고 새 주문에는 나오지 않습니다.)

### 답 입력 규칙

- 쓸 수 있는 글자: 숫자 `0~9`와 소수점 `.` 한 개, 최대 8칸. 음수·쉼표·문자는 입력되지 않거나 안내가 나옵니다.
- `0.5`와 `0.50`, `1`과 `1.00`처럼 같은 수는 모두 같은 답으로 봅니다(정확한 십진 계산, 부동소수점 미사용).
- 다음은 **입력 형식 안내**만 하고 답으로 확정하지 않습니다(오답으로 세지 않음): 빈칸, 소수점 두 개(`1.2.3`), 소수점으로 끝남(`1.`), 소수점으로 시작(`.5` — 화면 키패드는 자동으로 `0.`을 붙여 줌), 불필요한 앞자리 0(`01.8`, `00.5`), 9칸 이상.
- 키보드: 숫자, `.`, `Backspace`(한 글자), `Esc`/`Delete`(전체 지우기), `Enter`(제출).

### 집계 기준 (마감 화면·학습 기록)

- 계산 문제 = 계산이 필요한 재료 계량 + 비교 문제. 손님이 정한 양을 그대로 넣는 계량은 따로 표시하고 계산 문제 수에서 뺍니다.
- 유효한 답 제출은 문제당 한 번이고, 문제 ID로 중복 집계를 막습니다. 입력 형식 오류는 세지 않습니다.
- 힌트 사용: 주문서의 힌트로 식을 공개했을 때 **아직 답을 내지 않은** 학습 과제를 힌트 사용으로 기록합니다(여러 번 열어도 한 번). 이미 답을 낸 문제의 기록은 바꾸지 않고, 이전 버전의 단계별 힌트 기록(1~3단계)은 그대로 보존합니다. 오답이면 해설이 바로 보이므로 ‘해설 확인’으로 기록됩니다.
- 2단계까지의 ‘처음엔 틀렸지만 고쳐서 해결’은 이전 기록에만 남고, 3단계 문제는 ‘정확 / 다르게 계량 / 해설 확인’으로 기록합니다.
- 마감 화면은 네 가지만: **오늘 수입**(이번 영업 판매금 합, 재료 구매로 줄지 않음), **응대한 손님**, **현재 소지금**(구매·보상금이 모두 반영된 실제 잔액, 음수면 −로 표시), **잘못 만든 포션**(틀린 재료 과제가 하나라도 있는 주문의 병 수 합 — 3병 주문이면 3병, 1병 주문은 1병).
- 하루 계산 문제 수(기력 포션 1문제, 바람 걸음 포션 2문제), 정확·다르게 계량, 힌트, 만족도, 복습 결과 등은 화면에서 뺐지만 영업 기록·학습 기록·내보낸 JSON에 그대로 남습니다.

## 저장과 이어하기

- 진행 상황은 행동할 때마다 자동 저장됩니다(localStorage 키 `moonlight-potion-shop/save`, 저장 버전 **9**: 버전 8에 주문별 보상금 `penalty`, 영업일 시작 복구 지점 `checkpoints`(최대 2개), 영업 중단 `gameOver`, 오프닝 `opening`이 더해짐).
- 새로고침하거나 창을 닫았다 열어도 그 화면 그대로 이어집니다: 손님 주문, 재료를 솥에 놓고 입력 중, 답을 낸 결과·해설 화면, 재료를 넣은 뒤, 젓는 중(진행 정도), 병에 담은 뒤, 판매 후 감사 반응, 마감 화면(덧문 닫힘). 짧은 연출(붓기·병 담기·덧문)은 다시 재생하지 않고 최종 모습으로 보입니다.

### 저장을 읽지 못할 때

저장이 손상되었거나(JSON 오류), 규칙에 맞지 않거나(예: 판매 기록과 돈이 맞지 않음), 이 게임보다 새로운 버전이면 **저장을 덮어쓰지 않고** 타이틀에 안내를 띄웁니다. 그동안에는 자동 저장도 멈춥니다. 다음 중에서 고를 수 있습니다.

- **읽지 못한 저장 내려받기(보관용)**: 원본을 파일로 보관
- **저장 데이터 가져오기**: 내보내 둔 정상 저장 파일로 복구
- **새로 시작하기**: 확인 후 저장을 지우고 처음부터 (이어하기는 누를 수 없음)

| 칠흑의 은하수 | 350 | 380 | 370 |

- **미리보기**: 사기 전에 실제 창구(마을길·손님·덧문·벽·테이블 순서 그대로) 또는 제작대에 입혀 봅니다. 돈·소유·저장된 장착은 바뀌지 않고 **돌아가기**(또는 `Esc`)를 누르면 원래 모습입니다. 미리보기에서 바로 **구매하고 적용**할 수 있습니다.
- 산 장식은 ‘보유’, 쓰는 장식은 ‘적용 중’으로 표시되고, 다시 장착은 무료입니다. 돈이 모자라면 필요한 금액을 알려 주고 결제하지 않습니다. 연달아 눌러도 한 번만 결제합니다.
- 창밖 **마을 배경은 상품이 아니며** 어떤 테마에서도 그대로입니다.

## 소리 설정

- 게임 중에는 **음소거** 단추(창구·마감은 오른쪽 위, 제작대는 왼쪽 아래)로 효과음을 바로 끄고 켭니다. **음량**(0~100%)은 타이틀 화면의 소리 설정에서 바꿉니다.
- 설정은 이 브라우저에 따로 저장됩니다(localStorage 키 `moonlight-potion-shop/settings`). 게임 저장과 섞이지 않으며, 저장이 없거나 망가졌으면 ‘켜짐·60%’로 시작합니다.
- 효과음: 버튼, 재료 집기·놓기, 액체 붓기, 가루 붓기, 젓기(막대를 잡고 움직이는 동안만), 젓기 완료, 정확(부드러운 두 음)·다름(낮고 짧은 두 음, 놀라지 않게), 병 담기, 판매, 덧문 열기·닫기. 배경음악은 없습니다.
- 브라우저 정책상 **첫 클릭·터치 뒤부터** 소리가 납니다. 소리를 낼 수 없는 환경(자동재생 차단, 오디오 미지원)이어도 게임은 그대로 진행됩니다.
- 새로고침·이어하기 때 지난 효과음을 다시 내지 않습니다. 교실에서 소리가 필요 없으면 끄기만 하면 됩니다.

## 현재 제한 사항 (다음 단계 예정)

- 창구와 손님은 PNG입니다. 손님은 그림 한 장이라 표정이 바뀌지 않고, 만족·아쉬움·불만족은 대사와 간단한 움직임으로 구분합니다.
- 휴대폰을 세로로 들면 가로 장면 전체가 작게 보입니다(그림을 자르거나 재배치하지 않음). 가로로 돌리기를 권하는 닫을 수 있는 안내가 나옵니다.
- 효과음은 합성음이라 단순합니다. 배경음악은 없습니다.
- 문제은행 대사는 원문(하오체) 그대로라, 토끼·표범 손님이 문제은행 주문을 할 때는 인사·반응만 그 손님의 말투입니다. 그래서 문제은행 주문은 가능하면 여우·늑대 손님에게 맡깁니다.
- 학습 기록은 이 브라우저에만 저장됩니다. 다른 기기로 옮기려면 ‘저장 데이터 내보내기·가져오기’를 쓰세요.
