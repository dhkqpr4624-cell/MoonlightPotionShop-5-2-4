# 🌙 달빛 포션 상점 (2단계)

초등학교 5학년 2학기 **「소수의 곱셈」** 을 반복 연습하는 2D 웹게임입니다.
밤에만 여는 포션 가게의 주인이 되어, 손님의 주문을 받고 **레시피의 1병당 재료량 × 병 수**를 계산해 포션을 만듭니다.
계산한 답이 곧 계량해서 솥에 넣는 재료량입니다. 답을 맞혀야 재료가 들어가고, 모든 재료가 들어가야 포션이 완성되고 판매금을 받습니다.

- 시간제한·인내심 감소 없음. 오답이나 힌트로 돈이나 손님을 잃지 않습니다.
- 서버·로그인·유료 API 없이 브라우저만으로 동작합니다. 진행 상황은 브라우저(localStorage)에 저장됩니다.
- 태블릿(화면 키패드)과 PC(키보드) 모두 지원합니다.

> 현재 버전은 **2단계(하루 영업·마감·저장)** 입니다: 손님 5명 = 하루 영업, 영업 마감 결과(덧문이 닫힌 가게), 다음 날 영업, 안정적인 저장·이어하기, 저장 데이터·학습 결과 내보내기·가져오기.
> 제조 내용은 1단계와 같습니다: 여우 손님, 별빛 포션(달빛 이슬 0.6mL · 별가루 0.25g), 여러 병 주문(학습 유형 ①②).
> 전체 설계는 [`docs/DESIGN.md`](docs/DESIGN.md), 2단계 변경·검증 보고서는 [`docs/PHASE2_REPORT.md`](docs/PHASE2_REPORT.md)에 있습니다.

## 1. 로컬에서 설치하고 실행하기

**준비물:** [Node.js](https://nodejs.org/ko) 22 LTS(22.18 이상) 또는 24 이상. 설치 후 터미널에서 `node -v`로 확인하세요.

```bash
# 프로젝트 폴더에서
npm install        # 처음 한 번 (package-lock.json이 생깁니다)
npm run dev        # 개발 서버 실행 → 터미널에 나온 주소(보통 http://localhost:5173)를 브라우저로 엽니다
```

그 밖의 명령:

| 명령 | 하는 일 |
|---|---|
| `npm test` | 계산·판정·게임 규칙 자동 테스트 (Node 내장 테스트 실행기) |
| `npm run typecheck` | TypeScript 타입 검사 |
| `npm run build` | 타입 검사 후 배포용 파일을 `dist/` 폴더에 만듭니다 |
| `npm run preview` | 만든 `dist/`를 로컬에서 미리 보기 |

> **package-lock.json 안내:** 이 ZIP은 패키지 저장소(npm)에 접근할 수 없는 환경에서 만들어져 `package-lock.json`이 들어 있지 않습니다. (1단계와 같음)
> 처음 `npm install`을 하면 자동으로 생기니, 그 파일도 함께 저장소에 올려 두면 이후 배포에서 같은 버전이 설치됩니다(`npm ci`).
> 올리지 않아도 배포 workflow가 `npm install`로 설치하므로 배포는 됩니다.

## 2. ZIP을 풀어 GitHub 저장소에 올리기

1. GitHub에서 새 저장소를 만듭니다. (예: `moonlight-potion-shop`, Public 권장 — 무료 계정은 Public 저장소에서 Pages를 쓸 수 있습니다)
2. `Moonlight-Potion-Shop-phase1.zip`의 압축을 풉니다. 압축을 풀면 `Moonlight-Potion-Shop` 폴더가 생깁니다.
3. **그 폴더의 안쪽 내용**(`package.json`, `index.html`, `src/`, `public/`, `.github/` 등)이 저장소의 **맨 위(루트)** 에 오도록 올립니다.
   `Moonlight-Potion-Shop` 폴더 자체를 한 단계 더 넣어 올리면 배포가 되지 않습니다.
   - **Git 사용 시:** 압축을 푼 폴더 안에서
     ```bash
     git init
     git add .
     git commit -m "달빛 포션 상점 1단계"
     git branch -M main
     git remote add origin https://github.com/<사용자이름>/<저장소이름>.git
     git push -u origin main
     ```
   - **웹 업로드 시:** 저장소 화면의 **Add file → Upload files**에 폴더 안의 파일과 폴더를 끌어다 놓고 **Commit changes**를 누릅니다.
     ⚠️ `.github`처럼 점(.)으로 시작하는 폴더는 컴퓨터에서 숨김 폴더라 빠지기 쉽습니다. 다음 항목으로 꼭 확인하세요.

## 3. `.github/workflows/deploy.yml`이 올라갔는지 확인하기

- 저장소 첫 화면의 파일 목록에 `.github` 폴더가 보여야 하고, 들어가면 `workflows/deploy.yml`이 있어야 합니다.
- 주소창에 `https://github.com/<사용자이름>/<저장소이름>/blob/main/.github/workflows/deploy.yml`을 입력해 열리는지 확인해도 됩니다.
- 없다면: 저장소에서 **Add file → Create new file**을 누르고 파일 이름 칸에 `.github/workflows/deploy.yml`을 입력한 뒤, ZIP 안의 같은 파일 내용을 붙여 넣고 커밋합니다.
  (Windows 탐색기: 보기 → 표시 → 숨긴 항목 / macOS Finder: `Cmd + Shift + .` 로 숨김 폴더를 볼 수 있습니다.)

## 4. Settings → Pages에서 Source를 GitHub Actions로 선택하기

1. 저장소 상단의 **Settings** → 왼쪽 메뉴 **Pages**로 갑니다.
2. **Build and deployment → Source**에서 **GitHub Actions**를 선택합니다. (저장할 버튼은 따로 없고 선택하면 바로 적용됩니다.)

## 5. 배포 완료 확인과 사이트 접속

1. 저장소 상단 **Actions** 탭에서 **Deploy to GitHub Pages** 실행을 엽니다.
   - Source를 GitHub Actions로 바꾸기 전에 push했다면 첫 실행이 실패했을 수 있습니다. 왼쪽에서 **Deploy to GitHub Pages** → 오른쪽 **Run workflow** → **Run workflow**를 눌러 다시 실행합니다.
2. `build`와 `deploy` 두 작업이 모두 초록색 ✓ 이 되면 배포 완료입니다(보통 1~3분).
3. `deploy` 작업 안이나 **Settings → Pages** 상단에 나온 주소로 접속합니다.
   주소 형식: `https://<사용자이름>.github.io/<저장소이름>/`
4. 이후에는 `main` 브랜치에 push할 때마다 자동으로 다시 배포됩니다.

### 이미 배포한 저장소를 2단계로 업데이트하기

1단계를 배포한 저장소(예: `MoonlightPotionShop-5-2-4`)는 설정을 바꿀 필요가 없습니다. 파일만 바꾸면 됩니다.

1. `Moonlight-Potion-Shop-phase2.zip`을 풀고, 폴더 **안쪽** 내용을 저장소 루트에 덮어써서 올립니다(웹 업로드: Add file → Upload files에 모두 끌어다 놓기).
2. 새로 생기는 파일과 바뀌는 파일은 `docs/PHASE2_REPORT.md`의 ‘GitHub 업데이트 안내’에 정리했습니다. 2단계에서 **지워야 하는 파일은 없습니다.**
3. `main`에 올리면 Actions가 자동으로 다시 배포합니다. `.github/workflows/deploy.yml`은 1단계와 같습니다.
4. 학생들이 쓰던 브라우저의 1단계 저장은 처음 열 때 자동으로 옮겨집니다(아래 ‘Phase 1 저장 데이터 옮기기’).
5. 저장소에 `package-lock.json`을 따로 올려 두셨다면 그대로 두세요. 이번 ZIP에는 들어 있지 않아 덮어쓰지 않습니다. 의존성 버전을 바꾸지 않았으므로 기존 lock 파일로 `npm ci`가 됩니다.

### 배포 방식 설명 (저장소 이름과 base 경로)

GitHub Pages 사이트는 `/<저장소이름>/` 하위 경로에서 열립니다. workflow가 저장소 이름을 읽어
`VITE_BASE_PATH=/<저장소이름>/` 환경 변수를 만들고, `vite.config.ts`의 `base`가 이 값을 사용합니다.
그래서 저장소 이름을 무엇으로 정하든 코드를 고칠 필요가 없습니다.

- 이미지·효과음은 `src/lib/assets.ts`의 `assetUrl()`로 경로를 만들어 base 경로가 자동으로 붙습니다.
- 화면 전환은 주소(URL)가 아니라 게임 상태로 하므로, 어느 화면에서 새로고침해도 404가 나지 않습니다.
- 저장소 이름이 `<사용자이름>.github.io`이면 루트(`/`)로 빌드합니다.
- 사용자 지정 도메인을 연결했다면 workflow의 `Set base path` 단계에서 `BASE_PATH="/"`로 바꾸세요.

## 게임 방법

1. **가게 문 열기** → 창구의 덧문이 열리고 첫 손님이 옵니다. 화면 위에 `밤 1일차 · 손님 1 / 5`처럼 일차와 손님 순서가 보입니다.
2. **주문 받기 → 제조대로** → 레시피북에서 1병당 재료량을 확인하고, 계산식(예: `0.6 × 3 = ?`)의 답을 키패드나 키보드로 입력해 **계량하기**를 누릅니다.
   - 키보드: 숫자, `.`, `Backspace`(한 글자), `Esc`/`Delete`(전체 지우기), `Enter`(계량하기)
   - `0.5`와 `0.50`처럼 같은 수는 모두 정답. 틀리면 재료는 들어가지 않고 안내가 나옵니다. **힌트 보기**로 3단계 도움을 받을 수 있습니다.
3. 두 재료를 모두 넣으면 **포션 완성하기** → **창구로 가져가기** → **포션 전달하기** → 판매금(병당 달빛 동전 5개)을 받고 손님이 감사 인사를 합니다.
4. **다음 손님 맞이하기**를 누르면 다음 손님이 옵니다. 하루에 손님 5명(주문 5건, 재료 계량 10문제)입니다.
5. 다섯 번째 손님에게 판매하면 **영업 마감** 버튼이 나옵니다. 누르면 손님이 떠나고 창구 덧문이 닫힌 뒤, 오늘의 결과가 나옵니다.
   - 결과: 영업 일차, 응대한 손님 수, 판매한 병 수, 오늘 판매금, 현재 소지금, 전체 문제 수, 첫 시도에 맞힌 문제, 다시 계산해서 해결한 문제, 힌트를 사용한 문제
6. **다음 날 영업**을 누르면 일차가 1 늘고, 덧문이 열리며 새 날의 첫 손님이 옵니다. **타이틀로**를 눌러 쉬어도 가게는 닫힌 채로 기다립니다.

시간제한과 손님 인내심 감소는 없고, 오답·힌트로 돈을 잃지 않습니다. 병 수는 2~9병이며 같은 병 수가 연달아 나오지 않습니다.

### 집계 기준 (마감 화면·학습 결과)

- 재료 하나의 계량 = 문제 하나. 틀리고 다시 입력해도 문제 수는 늘지 않습니다.
- **첫 시도에 맞힘**: 처음 제출한 답이 정답인 문제
- **다시 계산해서 해결**: 처음에는 틀렸고 고쳐서 맞힌 문제
- **힌트를 사용한 문제**: 정답을 내기 전에 힌트를 한 번 이상 본 문제(여러 단계를 봐도 1번). 힌트를 보고 첫 시도에 맞히면 ‘첫 시도에 맞힘’과 ‘힌트 사용’에 모두 들어갑니다.
- 빈칸·`1.`처럼 형식이 잘못된 입력은 시도로 세지 않습니다.

## 저장과 이어하기

- 진행 상황은 행동할 때마다 브라우저(localStorage, 키 `moonlight-potion-shop/save`)에 자동 저장됩니다. 저장 버전은 **2**입니다.
- 새로고침하거나 창을 닫았다 열어도 **그 화면 그대로** 이어집니다: 손님 주문 화면, 오답 후 다시 입력 중, 첫 재료를 넣은 뒤, 두 번째 재료를 입력하는 중(입력 중인 숫자 포함), 포션 완성 후 전달 전, 판매 후 감사 인사, 마감 화면(덧문 닫힘).
- 하루의 주문 5건은 영업을 시작할 때 한꺼번에 정해져 저장됩니다. 새로고침해도 주문이 바뀌지 않습니다.
- 판매금은 주문마다 한 번만 지급됩니다. 버튼을 여러 번 누르거나, 판매 직후 새로고침하거나, 덧문 연출 도중 새로고침해도 돈이 다시 들어오거나 일차가 두 번 늘지 않습니다. 이미 지나간 손님의 주문으로 돌아가지도 않습니다.
- 덧문의 열림·닫힘은 저장된 영업 상태(영업 중/마감)로 정해집니다. 연출 도중 새로고침하면 연출 없이 최종 모습으로 보입니다.
- 브라우저의 방문 기록·사이트 데이터를 지우면 저장도 지워집니다. 중요한 진행은 아래 ‘저장 데이터 내보내기’로 보관하세요.

### Phase 1 저장 데이터 옮기기(마이그레이션) 규칙

1단계 게임을 하던 브라우저에서 2단계를 처음 열면, 1단계 저장(버전 1)을 자동으로 2단계 형식(버전 2)으로 옮깁니다.

| 1단계 저장 항목 | 2단계에서 |
|---|---|
| 달빛 동전(소지금), 누적 판매 통계, 판매금 지급 기록, 주문 번호 | 그대로 보존 |
| 학습 기록 | 모두 보존. 문제 ID를 붙이고, 하루 영업이 없던 시절의 기록은 **일차 0**으로 표시 |
| 판매 전인 진행 중 주문(주문 대기·제조 중·완성 후 전달 전) | **1일차의 첫 번째 손님**으로 이어서 진행(넣은 재료·입력 중인 답 유지). 나머지 손님 4명은 새로 준비. 이 주문의 기록은 1일차로 표시 |
| 판매가 끝난 주문 또는 주문 없음 | ‘가게 문 열기’를 누르면 1일차를 새로 시작 |

- 옮기기 전의 원본은 `moonlight-potion-shop/backup-v1` 키에 그대로 보관합니다.
- 옮긴 뒤에는 타이틀에 “이전 버전의 저장을 새 형식으로 옮겼어요” 안내가 나옵니다.
- 1단계에서 내보낸 파일은 없지만, 버전 1 형식의 JSON을 ‘저장 데이터 가져오기’로 넣어도 같은 규칙으로 옮겨 가져옵니다.

### 저장을 읽지 못할 때

저장이 손상되었거나(JSON 오류), 규칙에 맞지 않거나(예: 판매 기록과 돈이 맞지 않음), 이 게임보다 새로운 버전이면 **저장을 덮어쓰지 않고** 타이틀에 안내를 띄웁니다. 그동안에는 자동 저장도 멈춥니다. 다음 중에서 고를 수 있습니다.

- **읽지 못한 저장 내려받기(보관용)**: 원본을 파일로 보관
- **저장 데이터 가져오기**: 내보내 둔 정상 저장 파일로 복구
- **지우고 새로 시작하기**: 확인 후 저장을 지우고 처음부터

| 저장 데이터 내보내기 | `moonlight-save-day<일차>-<날짜>.json` | 다른 기기·브라우저에서 이어 하기 위한 게임 상태 전체(`format: moonlight-potion-shop/save`, `saveVersion: 2`) |
| 저장 데이터 가져오기 | 위 파일(또는 버전 1 저장 JSON) | 검사 후, 현재 저장과 가져올 파일을 비교해 보여 주고 **바꾸기**를 눌러야 적용 |
| 학습 결과 내보내기 | `moonlight-learning-day<일차>-<날짜>.json` | 개인 식별 정보 없이 문제별 기록(식, 정답, 첫 답, 첫 시도 정오, 시도 횟수, 힌트 사용, 학습 유형, 일차·손님 순서)과 영업별 집계 |

가져오기 검사 항목: JSON 형식, 파일 종류, 저장 버전, 필수 값과 자료형, 레시피·손님·재료 ID가 게임 데이터에 있는지, 레시피 기본량과 정답 계산이 맞는지, 손님 순서와 주문 상태(지나간 손님은 판매 완료, 아직 안 온 손님은 대기), 판매 기록과 오늘 판매금·지급 기록의 일치, 마감 상태와 결과 기록의 일치.
잘못된 파일이면 이유를 보여 주고 **현재 저장은 그대로** 둡니다. 학습 결과 파일은 기록 확인용이라 가져올 수 없습니다.

### 그림 교체하기

지금 그림은 코드로 그린 **임시 그래픽**이라 그림 파일이 없어도 동작합니다.
- 손님: `public/assets/customers/fox.png`처럼 넣고 `src/data/customers.ts`의 해당 손님에 `image: "assets/customers/fox.png"`를 추가합니다(파일을 못 읽으면 자동으로 임시 그래픽).
- 덧문·영업 종료 표지판: `public/assets/shop/`에 그림을 넣고 `src/data/shopArt.ts`의 `shutterLeft`, `shutterRight`, `closedSign`에 경로를 적습니다. 덧문 한 짝은 가로:세로 = 350:500 비율에 맞춰 늘어납니다.

## 현재 제한 사항 (다음 단계 예정)

- 손님 그림은 여우 1종, 포션은 별빛 포션 1종, 주문은 여러 병 주문(학습 유형 ①②)만 있습니다.
- 학습 유형 ③~⑦, 맞춤 배수·소수점 비교 주문, 교사 설정 화면, 학습 기록 보기 화면, 틀린 유형 복습 문제 → 3단계
- 도감·해금(4단계), 가게 꾸미기(5단계), 최종 그래픽·효과음(6단계)
- 학습 결과는 파일로 내보낼 수 있지만, 게임 안에서 여러 날의 기록을 모아 보는 화면은 아직 없습니다.
