# 《달빛 포션 상점》 설계 초안

초등 5학년 2학기 「소수의 곱셈」 반복 연습 게임. 이 문서는 전체 설계이며, 현재 구현은 **3단계**까지입니다. 3단계에서 기획이 바뀐 부분(오답으로도 제조, 품질별 판매금, 계산식 숨김, 주문 4유형, 유형 자동 소개, 복습)은 `docs/PHASE3_REPORT.md`가 이 문서보다 우선합니다.

## 0. 핵심 원칙 (모든 단계 공통)

- 포션 제조의 핵심 행동 = 소수 곱셈 문제 풀이. 입력한 답이 곧 계량해서 넣는 재료량이다.
- 정답을 입력하지 않으면 재료가 투입되지 않고, 모든 학습 재료가 투입되지 않으면 포션이 완성되지 않으며, 완성되지 않으면 판매금이 없다.
- 자동 계산·문제 건너뛰기·방치 수익 없음. 시간제한·인내심 감소 없음.
- 오답 = “계량 다시 하기”. 돈·손님을 잃지 않는다. 힌트도 무료.
- 정답 후 계량 → 투입 → 병 담기는 1~2초의 자동 연출.

## 2. 학습 유형 ↔ 주문 유형

| 학습 유형 | 식의 모양 | 주문 유형 | 예 |
|---|---|---|---|
| ① 소수 한 자리 × 자연수 | 1병당 양 × 병 수 | A 여러 병 | 달빛 이슬 0.6mL × 3병 = 1.8 |
| ② 소수 두 자리 × 자연수 | 1병당 양 × 병 수 | A 여러 병 | 별가루 0.25g × 3병 = 0.75 |
| ③ 자연수 × 소수 한 자리 | 자연수 기본량 × 배수 | B 맞춤 배수 | 용의 꿀 4mL의 0.3배 = 1.2 |
| ④ 자연수 × 소수 두 자리 | 자연수 기본량 × 배수 | B 맞춤 배수 | 솜사탕 가루 3g의 0.25배 = 0.75 |
| ⑤ 소수 한 자리 × 소수 | 소수 기본량 × 배수 | B 맞춤 배수 | 잎가루 0.4g의 0.5배 = 0.2 |
| ⑥ 소수 두 자리 × 소수 | 소수 기본량 × 배수 | B 맞춤 배수 | 은빛 가루 0.15g의 0.4배 = 0.06 |
| ⑦ 곱의 소수점 위치 변화 | 한 인수가 10배·1/10 | C 소수점 비교 (오늘의 특별 주문) | 2.4×3=7.2 → 0.24×3=□ |

- A: 병 수는 자연수(기본 2~9). 학습 재료 2종이 모두 문제 → 주문당 2문제.
- B: 1병, “○○는 **기본량의 0.5배**”. 배수를 바꾼 재료만 문제, 나머지는 기본량 자동 투입. 병 수와 배수를 동시에 바꾸는 주문은 초기 버전에서 제외.
- C: 기본 레시피를 바꾸지 않고 “오늘의 특별 주문: 진한/연한 원액이라 기본량이 10배/10분의 1”로 표시. 앞 제조식을 보여 주고 이번 곱을 구한다. 필요 시 “몇 배가 되었나요?” 짧은 비교 문제 추가.
- 하루 5명 × 평균 2문제 ≈ 8~12문제.
- 유형별 범위(병 수 범위, 허용 배수 목록, 자릿수)는 `learningTypes` 설정 데이터로 관리하고, 교사 설정에서 유형을 켜고 끈다. 가구·성장과 무관.

## 3. 재료·레시피 초안 (1병당 첨가물, 고정)

포션 = **기본 용액(자동 투입, 한 병 30mL)** + 마법 첨가물. 첨가물은 기본 용액에 섞는 양이며, 첨가물의 합이 병의 전체 용량이 아니다. 액체 첨가물은 mL, 가루는 g.

| 포션 | 학습 재료 1 | 학습 재료 2 | 모습 | 지원 유형 |
|---|---|---|---|---|
| 별빛 포션 | 달빛 이슬 0.6mL | 별가루 0.25g | 푸른 액체, 별 입자 | ①② / ⑤⑥ |
| 새싹 포션 | 숲의 이슬 1.2mL | 잎가루 0.4g | 초록 액체, 작은 잎 | ① / ⑤ |
| 안개 포션 | 구름 원액 0.8mL | 은빛 가루 0.15g | 보랏빛 액체, 안개 | ①② / ⑤⑥ |
| 온기 포션 | 햇살 원액 1.5mL | 붉은 열매즙 0.3mL | 주황 액체, 따뜻한 빛 | ① / ⑤ |
| 파도 포션 | 파도 원액 2.4mL | 진주 가루 0.35g | 청록 액체, 물방울 | ①② / ⑤⑥ / ⑦ |
| 용기 포션 | 용의 꿀 4mL | 불꽃 가루 2g | 빨간 액체, 불꽃 방울 | ③④ (B 전용) |
| 꿈결 포션 | 꿈꽃 시럽 6mL | 솜사탕 가루 3g | 분홍 액체, 구름 거품 | ③④ (B 전용) |

- 자연수 기본량 레시피는 여러 병 주문에 쓰지 않는다(자연수×자연수는 범위 밖).
- 레시피별 지원 유형은 코드가 기본량의 자릿수로 계산한다(`coverage`). 켜진 유형을 낼 레시피가 없으면 시스템이 경고하며, 기본량을 몰래 바꾸지 않는다.

손님: 여우 수인 코코, 토끼 수인 보리, 고양이 수인 나비, 늑대 수인 달이, 작은 용 뿌뿌, 버섯 정령 송이. 외형은 난이도와 무관.

## 4. 데이터 구조 (분리)

```
data/ingredients.ts   Ingredient { id, name, unit:'mL'|'g', kind:'liquid'|'powder', color }
data/recipes.ts       Recipe { id, name, baseSolution, additives:[{ingredientId, amount:"0.6"}], look, pricePerBottle }
data/customers.ts     Customer { id, name, species, palette, lines:{order[], thanks[], retry[]}, unlock }
data/learningTypes.ts LearningTypeConfig { id, label, orderKind, multiplicandDecimals, multiplierSpec }
data/gameConfig.ts    병 수 범위, 가격 등
game/types.ts         Order, IngredientTask, Problem, AttemptRecord, GameState
game/orderFactory.ts  문제 덱(최근 문제 회피 → 소진 시 섞어서 재사용)으로 주문 생성
game/feedback.ts      입력 형식 검사 결과·오답 진단·단계별 힌트
game/reducer.ts       순수 상태 전이(모든 규칙과 가드)

```

- 소수는 모든 데이터에서 **문자열**("0.25")로 보관하고, 계산은 `{digits: bigint, scale: number}`로 변환해 정확히 한다. 부동소수점 미사용.
- Problem은 `{ operation:'multiply', a, b, answer, learningType, unit, prompt }` 형식. 3단계 이후 “식 세우기” 활동은 Problem에 `stage:'compose'`를 추가하는 방식으로 확장.
- 학습 기록(AttemptRecord): 최초 답·최초 정오·시도 횟수·힌트 단계·최종 해결·학습 유형·인수와 정답.
- 성장(2~5단계): `progress { daysCompleted, unlockedRecipes, potionDex, customerDex }`, `decor { owned, equipped }` 를 별도 슬라이스로.

## 5. 영업 상태 흐름

```
title ─▶ counter:arrived ─(주문 받기)─▶ workbench:brewing
  workbench:brewing ── 재료 선택 → 답 입력 → 계량하기
       ├ 형식 오류 → 안내만 (시도 아님)
       ├ 오답 → 투입 안 함, 안내·힌트, 다시 입력
       └ 정답 → 계량·투입 연출, task=done
  (모든 학습 재료 done) ─(포션 완성)─▶ bottled ─▶ counter:bottled
  counter:bottled ─(전달하기)─▶ paid (판매금 1회 지급) ─(다음 손님)─▶ counter:arrived
  2단계(구현): 다섯 번째 손님 paid ─(영업 마감)─▶ day.status=closed (덧문 닫힘, 결과 기록)
             ─(다음 날 영업)─▶ 일차+1, 주문 5건 생성, day.status=open (덧문 열림) ─▶ counter:arrived
  5단계 이후: 마감 결과 → 꾸미기 / 다음 영업
```

가드(리듀서): 완성은 모든 task done일 때만, 지급은 `bottled → paid` 전이에서만 1번. 상태는 매 전이마다 저장되므로 새로고침·중복 클릭으로 돈이 두 번 들어오지 않는다.

## 7. 3단계에서 바뀐 규칙 (이 문서 앞부분보다 우선)

- 제조: 재료를 솥에 놓기(클릭·드래그·키보드) → 계량 문제 → 유효한 답 1회로 확정 → 결과·해설 → 투입 → 젓기(이동 거리 누적 또는 버튼) → 병에 담기(품질·판매금 확정) → 전달.
- 오답이어도 학생이 입력한 양으로 제조한다. 품질: 두 재료 정확 100%, 하나 80%, 둘 다 다름 60% (정수, 버림).
- 기본 계량 화면에는 계산식·정답을 보이지 않고, 힌트 3단계(어림 → 식·방법 → 계산 과정·정답)로 보여 준다.
- 주문: 여러 병 / 맞춤 배수(기본 레시피의 ○배, 기본 용액도 같은 배수) / 생활 소재 특별 주문(계산한 숫자를 재료량으로, 단위 변환 아님, 다른 재료는 기본량 지정) / 곱의 변화 비교(⑦, 선택형, 양은 자동 계량). 특별 주문 판매금 20.
- 레시피 4종: 별빛(0.6, 0.25) · 용기(4, 2) · 새싹(0.8, 0.4) · 안개(0.35, 0.15).
- 학습 유형은 영업 완료마다 ①② → ③④ → ⑤⑥ → ⑦ 자동 소개 (일차와 별개, 정답률과 무관). 교사·학생 설정 화면 없음.
- 오답 문제는 복습 후보 → 다음 영업부터 같은 유형·다른 인수로 하루 최대 1건.

## 8. 4단계에서 바뀐 것 (시각적 완성도 — 게임 규칙은 3단계와 같음)

- **젓기 버튼 삭제.** 젓기는 막대 직접 조작(마우스·터치 드래그, 보조로 키보드 ←→)만. 입력 계산은 `src/game/stirInput.ts`(순수 로직):
  솥 액체 타원 기준 정규화 좌표 → 막대 끝은 반지름 0.82 안으로 제한 → 한 번의 이동은 최대 0.35로 자르고 0.01 미만 떨림은 무시 → 이동 거리 × 14가 진행도(100 완료).
  한 포인터(손가락)만 인정, Pointer Capture 사용, `pointercancel`·포인터 놓침·창 blur·화면 숨김·화면 이탈 시 잡기 해제. 진행도는 3단계와 같은 `STIR` 액션(한 번 최대 25)으로 저장.
- 연출은 상태와 분리: 붓기(`state.pour.seq`가 이번 화면에서 바뀐 때만), 젓기 완료 빛(이번 화면에서 100을 넘긴 때만), 병 담기·판매·손님 등장/퇴장·덧문. 보상·재료·일차는 버튼을 누른 즉시 리듀서가 처리하고 연출 끝을 기다리지 않는다. 새로고침하면 최종 모습만 보인다.
- 효과음: Web Audio 합성(`src/audio/sfx.ts`), 음원 파일 없음. 첫 사용자 입력 뒤에만 AudioContext 생성. 설정은 `moonlight-potion-shop/settings`(버전 1, 게임 저장 v3와 별도).
- 그림: SVG 코드(배경 4장은 `public/assets/shop/*.svg`, 손님·포션·재료·솥·덧문·아이콘은 컴포넌트). 이모지를 핵심 그래픽·아이콘으로 쓰지 않는다.
- 저장 형식은 바뀌지 않음(v3). 3단계 저장은 그대로 열린다.
