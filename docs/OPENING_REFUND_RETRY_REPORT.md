## 1. 잘못 만든 포션 → 피해 보상금

| 결과 | 판매금 | 피해 보상금 |
|---|---|---|
| 모든 필수 재료를 정확히 계량 | 정상 판매금 전액 | 없음 |
| 하나라도 잘못 계량 | **0G** | **정상 판매가 총액 ÷ 3, 반올림**(정수 G) |

**판정과 계산 규칙**
- 판정에는 기존 품질 판정(`qualityOf`)을 그대로 씁니다. 품질이 `great`가 아니면 잘못 만든 포션입니다.
- 비교 문제(⑦)는 고른 답의 정오로 판정합니다.
- 보상금은 **주문당 한 번** 계산합니다. 병 수나 틀린 재료 수를 다시 곱하지 않습니다.
- 계산 예: 21G → 7G, 24G → 8G, 30G → 10G, 10G → 3G, 35G → 12G, 1G → 0G. 상한·하한은 없습니다.
- 보상금과 상관없는 것: 힌트 사용, '네?', 숫자 입력 형식 오류(답으로 확정되지 않음), 아직 전달하지 않은 주문.

**돈이 움직이는 시점**
- 병에 담을 때 판매금과 보상금을 함께 확정해 주문에 저장합니다(`reward`, `penalty`).
- 돈은 **창구에서 전달하는 순간(DELIVER) 한 번만** 움직입니다.
- 이미 지급 기록(`paidOrderIds`)이 있는 주문은 다시 처리하지 않습니다. 그래서 연속 클릭·새로고침·이어하기로 중복 차감되지 않습니다.

**창구·자동 솥·기록 표시**
- 창구에는 손님 반응과 함께 "잘못 만든 포션이라 판매금은 0G. **보상금 −8G**를 손님에게 드렸어요."가 나오고, 떠오르는 글씨 `보상금 −8G`가 함께 보입니다.
- 마녀의 자동 솥으로 만들어도 같은 `bottle()` 함수를 거치므로 결과와 보상금이 똑같습니다.
- 마감 화면 구성은 그대로입니다.
  - `오늘 수입`: 판매금만 더합니다.
  - `현재 소지금`: 구매와 보상금이 모두 반영된 실제 잔액입니다. 음수는 `−20`처럼 표시합니다.
- 학습 기록의 '손님 반응' 표에 '보상금' 칸을 더했습니다. 주문 결과 기록(`orderLog`)에는 `penalty`가 남습니다.

## 2. 손님 대기 움직임

손님 그림·크기·서는 자리는 그대로 두고, 대기 애니메이션만 바꿨습니다.

| | 이전 | 이번 |
|---|---|---|
| 주기 | 4.2초 숨쉬기 | 숨쉬기 3.2초마다 한 번, 좌우 흔들림 한 번 왕복은 6.4초 |
| 위아래 | 2px, 1.005배 | 4px, 1.008배 |
| 좌우 | 없음 | 발밑을 기준으로 ±0.7° |

**안전 확인**
- 손님 그림의 아래 약 77px(캔버스 기준)은 카운터 뒤에 가려 있습니다. 그래서 4px 올라가도 떠 보이지 않습니다. 브라우저 점검에서 손님 그림 아래 끝이 늘 카운터 윗면보다 아래인 것을 확인했습니다.
- 귀 끝이 잘리지 않도록, 손님 크기를 정할 때 움직임만큼 여유(14px)를 미리 남깁니다(`NPC_MOTION_HEADROOM`).
- 등장·퇴장, 대사창 위치, 카운터 뒤 가림 순서, 덧문 연출은 그대로입니다.
- 움직임 줄이기 설정(`prefers-reduced-motion`)에서는 기존처럼 멈춥니다.

## 3. 새 게임 오프닝

**시작 조건**
- '새로 시작하기'를 확정한 뒤에만 시작합니다. 진행이 있으면 교체 확인에서 '지우고 새로 시작'을 눌러야 합니다.
- '이어하기'로 기존 게임에 들어갈 때와 이전 저장에는 나오지 않습니다.

**연출 순서**
1. 타이틀 PNG를 그대로 쓰고, 시작·이어하기 버튼과 보조 버튼은 숨깁니다.
2. 그림이 상점 문·진열창 쪽(가로 48%, 세로 58% 지점)으로 5.5초 동안 1.00배에서 **1.12배**까지 확대된 뒤 멈춥니다.
3. 확대가 시작되면 아래쪽에 나무 테두리 대화창(이름표 '나 · 달빛 포션 상점 주인')이 나타납니다.
4. 대사 세 개를 한 번에 하나씩 문구 그대로 보여 줍니다.

**넘기기와 이어 보기**
- '다음' 버튼이나 화면 빈 곳을 클릭·터치하면 넘어갑니다. 자동으로 넘어가지 않습니다.
- 한 번에 한 대사만 넘어갑니다.
  - 버튼 클릭이 화면 클릭으로 번지지 않게 막습니다.
  - 넘길 때 지금 보고 있는 대사 번호를 함께 보내, reducer가 그 번호일 때만 받아들입니다.
- 마지막 대사를 넘기면 실제 창구로 전환 → 기존 덧문 열기 → 첫 손님 등장 → 기존 첫 주문 튜토리얼 순서로 이어집니다. 튜토리얼 안내는 덧문이 다 열린 뒤에 나옵니다.
- 보고 있는 대사 번호는 저장됩니다(`opening.line`). 오프닝 중 새로고침하면 타이틀에 "새 가게 오프닝 (3/3)"이 표시되고, '이어하기'를 누르면 그 대사부터 다시 보입니다(확대는 끝난 모습).
- 오프닝을 마친 뒤에는 새로고침·이어하기·전날 복구로 다시 나오지 않습니다.

## 4. −50G 이하 영업 중단과 전날 복구

**음수 소지금과 영업 중단**
- 소지금은 보상금 때문에 음수가 될 수 있습니다. 상점·서랍 구매는 이전처럼 잔액이 가격보다 적으면 막힙니다.
- 전달로 정산을 마친 직후 소지금이 **−50G 이하**면 영업 중단(`gameOver`)을 저장합니다.
  - 정확히 −50G, 그리고 −47G에서 8G를 내 −55G가 된 경우 모두 영업 중단입니다.
  - −49G에서는 영업을 계속합니다.
- 영업 중단 중에는 reducer가 처음 화면 이동·이어하기·복구 말고는 받지 않습니다. 다음 손님·마감·다음 영업·구매·해금·제조가 모두 막힙니다.
- 창구에는 손님 반응과 보상금을 먼저 보여 주고, 약 1.6초 뒤 '영업 중단' 화면이 나타납니다. 새로고침 후 이어하기 하면 바로 나타납니다.
- 화면 내용:
  - 제목 "영업 중단"
  - 이유 "보상금 지급으로 소지금이 −50G 이하가 되었습니다."
  - 현재 소지금
  - 복구 안내와 '전날부터 다시 시작 (4일차)' 버튼

**복구 기준**

| 상황 | 돌아가는 곳 | 버튼 |
|---|---|---|
| N일차에 중단(전날 복구 지점 있음) | **N−1일차 영업 시작 상태** | 전날부터 다시 시작 (N−1일차) |
| 1일차에 중단 | 1일차 영업 시작 상태 | 1일차 처음부터 다시 시작 |
| 업데이트 전 저장이라 전날 복구 지점이 없음 | 확보된 그날 영업 시작 상태 | N일차 처음부터 다시 시작 |
| 복구 지점이 아예 없음(업데이트 전 저장, 영업 도중) | 복구하지 않음. 저장은 지우지 않음 | '처음 화면으로' + '저장·기록 관리'의 가져오기 안내 |

**복구 지점에 담기는 것**
- 영업일을 여는 순간(새 게임 시작, 다음 영업)의 게임 상태 전체를 저장합니다. 단, 복구 지점·영업 중단·오프닝 정보는 빼서 중첩되지 않게 합니다.
- 오늘과 전날 것 두 개만 남깁니다.
- 함께 되돌아가는 것:
  - 소지금, 재료 해금, 상점 구매·장착
  - 그날 주문 5건(같은 주문), 주문 번호·문제 덱
  - 학습 기록, 복습 후보, 주문 결과 기록, 영업 결과, 누적 통계, 지급 기록
- 그래서 복구 지점 이후의 판매·구매·보상금·기록이 함께 사라지고, 중복 지급·중복 집계가 생기지 않습니다(테스트로 확인).

**복구 뒤 처리**
- 오프닝은 다시 나오지 않습니다.
- 이미 끝낸(또는 건너뛴) 튜토리얼은 다시 시작하지 않습니다.
- 그날 시작 상태이므로 새 유형 소개 카드는 다시 나옵니다.
- 복구 뒤에는 창구에서 덧문이 다시 열립니다.
- 복구한 날 이후의 복구 지점은 버립니다. 그날을 다시 마치면 다음 날 복구 지점이 새로 생깁니다.

## 5. 저장 호환 (버전 8 → 9)

| 버전 8 저장 | 버전 9에서 |
|---|---|
| 모든 진행 | 그대로 |
| 이미 전달(정산)한 주문 | 그때 받은 판매금(품질별 감액) 그대로. `penalty`가 없는 '이전 규칙 정산'으로 보고, 검사는 이전 감액 규칙으로 합니다. 다시 계산하지 않습니다 |
| 병에 담았지만 아직 전달하지 않은 주문 | 돈이 움직이기 전이므로 새 규칙으로 다시 정합니다(올바르면 정상 판매금, 잘못 만들었으면 판매금 0 + 보상금) |
| 새 항목 | `opening: null`(오프닝 없음), `gameOver: null`, `checkpoints: []` |
| 복구 지점 | 지어내지 않습니다. 단, 오늘 첫 손님 주문을 받기 전(판매 0)인 저장은 그 상태가 곧 오늘의 영업 시작 상태이므로 오늘 복구 지점으로 둡니다 |

- 원본은 `moonlight-potion-shop/backup-v8`에 보관합니다. 버전 1~7 저장도 8을 거쳐 9로 옮겨집니다.
- 저장 검사에 추가된 것:
  - 음수 소지금 허용
  - 보상금과 계량 결과의 일치
  - 영업 중단 정보와 소지금의 일치
  - 각 복구 지점이 완전한 '영업 시작' 상태인지
  - 오프닝 대사 번호
- 복구 지점 때문에 저장 크기가 커질 수 있어, 가져오기 파일 한도를 2MB에서 6MB로 올렸습니다.

## 6. 검증

| 검사 | 결과 |
|---|---|
| 단위·규칙 테스트 `npm test` | **155 / 155 통과**. 새 `tests/refund-gameover-opening.test.ts` 16개 포함, 기존 기대값은 새 규칙에 맞게 갱신 |
| 타입 검사(`strict`) | 오류 0 |
| 문제은행 변환 검사 | 통과(180문항) |
| 브라우저 종단 점검(Chromium, 배포와 같은 하위 경로) | **216 / 216 통과**. 기존 161 + 이번 55. 콘솔 오류 0, 404 0 |

**우선 시나리오별 확인**
1. 정상 24G 주문은 +24G입니다. 잘못 만든 24G 주문은 판매금 0, −8G입니다(재료 1개 오답이든 2개 오답이든 8G 한 번).
2. 전달 버튼 연속 클릭·더블클릭, 병에 담은 상태에서 새로고침, 전달 뒤 새로고침 모두 차감·지급이 한 번만 일어납니다.
3. −49G에서는 '다음 손님'이 가능합니다. −50G와 −55G에서는 영업 중단이고, 다음 손님·마감·구매가 막힙니다.
4. 5일차 중단 → 4일차 시작 상태로 복구했을 때, 소지금·주문 5건·상점 구매·장착·해금·학습 기록·복습·주문 기록·영업 결과·지급 기록·덱이 4일차 시작 복구 지점과 똑같습니다. 복구 후 4일차를 다시 마쳐도 4일차 기록이 중복되지 않습니다(테스트). 브라우저에서도 영업 중단 → 새로고침 → 이어하기(중단 유지) → 복구 → 새로고침까지 확인했습니다.
5. 1일차 실패는 1일차 시작으로 돌아가고, 오프닝·튜토리얼이 다시 나오지 않습니다. 복구 지점 없는 v8 저장은 복구 버튼 없이 안내만 나오고 저장은 그대로입니다. 첫 손님 전 v8 저장은 그날 복구 지점이 생깁니다.
6. 새 게임에서만 오프닝이 나옵니다.
   - 교체 확인을 취소하면 나오지 않고, 확인하면 시작합니다. 이어하기로는 나오지 않습니다.
   - 대사 문구가 정확하고, 버튼·빈 곳 클릭·터치 한 번에 한 대사씩 넘어갑니다.
   - 6.5초를 기다려도 자동으로 넘어가지 않고, 확대는 1.12배에서 멈춥니다.
   - 오프닝 중 새로고침 → 이어하기 하면 그 대사부터 나옵니다.
   - 마지막 대사 뒤 덧문이 열리는 동안에는 튜토리얼이 없고, 열린 뒤 여우 손님과 튜토리얼이 나옵니다.
7. 화면 크기
   - 오프닝 대화창이 1366×768, 1024×768, 1920×1080, 844×390, 390×844에서 모두 무대 안에 들어옵니다.
   - 손님 움직임(위아래 3~4.5px, 좌우 ±0.4° 이상)과 카운터 가림을 1366×768, 844×390, 390×844에서 확인했습니다.
   - 움직임 줄이기 설정에서는 손님 움직임이 멈추고, 오프닝 확대는 바로 끝난 모습입니다.
   - 기존 주문·자동 솥·이어하기·튜토리얼 점검도 모두 통과했습니다.

| 75% | 5 | 6 | 51 | 0% |
| 50% | 2 | 2 | 19 | 63% (중앙 40일차) |
| 35% | 1 | 1 | −4 | 95% (중앙 18일차) |

- 이전 규칙(품질별 감액)에서는 75% 플레이가 약 32일에 8종을 모두 열었습니다. 이번 규칙에서는 45일 안에 다 열리지 않습니다. 재료가 2~3개인 주문은 과제 하나만 틀려도 판매금이 0이기 때문입니다.
- 정답률이 낮은 학생은 영업 중단 → 전날 복구를 반복할 수 있습니다.
- 요청하신 규칙대로 구현했고, 가격·해금 비용은 바꾸지 않았습니다.
- 균형을 맞추려면 재료 해금 가격 조정이나 보상금 비율 조정 같은 후속 조정을 검토해 볼 수 있습니다.
- 기존 '30일 균형' 테스트는 이번 규칙에 맞게 바꿨습니다.
  - 모두 정답이면 24~32일에 모두 해금
  - 보통 플레이(75%)는 10일 안에 첫 새 레시피, 30일까지 4종 이상

## 8. 실행하지 못한 것

- **진짜 `npm install`·`vite build`·`tsc -p`**: 이 환경은 npm 레지스트리에 접속할 수 없습니다.
  - 대신 esbuild로 같은 base(`/MoonlightPotionShop-5-2-4/`) 정적 빌드를 만들어 브라우저에서 점검했습니다.
  - 타입 검사는 React 타입을 최소한으로 흉내 낸 파일로 `strict` 검사를 했습니다.
  - 저장소에 올린 뒤 GitHub Actions(`npm ci && npm run build`) 결과를 한 번 확인해 주세요.
- **실제 태블릿·휴대폰**: Chromium 기기 흉내(터치·화면 크기)만 했습니다.
- **GitHub 쓰기·배포**: 요청대로 하지 않았습니다.
