- GitHub에는 아무것도 하지 않았습니다(브랜치·커밋·푸시·PR·파일 수정·설정 변경·workflow·배포 실행 없음).

## 1. 바뀐 화면

### 레시피북 (`src/components/BookPopup.tsx`)

| 쪽 | 내용 |
|---|---|
| 왼쪽 면 | 고른 레시피만 크게: 포션 그림과 이름, ‘1병당 재료’, 재료마다 [그림] 이름과 양·단위 |
| 오른쪽 면 | ‘레시피 고르기’ 목록. 잠긴 레시피는 자물쇠와 ‘잠김’ 표시 |

- 잠긴 레시피를 고르면 ‘잠김’과 필요한 재료(이름·있음/해금 필요)만 보입니다. 양은 보이지 않습니다.
- 지운 것:
  - 맑은 물·기본 용액 안내
  - 만드는 순서, 중복 제목, 보충 문장
  - 이번 주문의 총량과 정답
- 물은 내부에서 자동으로 들어가며(`autoAdditions`), 학생 화면의 레시피 설명과 해금 안내에는 나오지 않습니다.
- 글자 크기는 책 너비에 따라 커집니다(container query). 1180×820 화면에서 양 숫자는 약 30px, 재료 이름은 약 22px입니다. 글자는 가운데 접힘선과 장식을 피한 종이 안쪽에만 놓았습니다.

### 이번 주문 팝업과 힌트

- 왼쪽 면에는 손님이 한 원래 대사와 ‘‘네?’ 쉬운 설명 보기’를 둡니다. 글자를 키웠습니다(대사 약 18px).
- 오른쪽 면의 ‘주문 내용’과 ‘지금 필요한 일’은 지우고 **힌트** 버튼 하나만 둡니다.
  - 누르기 전에는 식이 보이지 않습니다. 팝업을 다시 열면 다시 숨겨집니다.
  - 누르면 재료별로 필요한 식만 보여 줍니다(`orderHints`, 실제 주문 데이터로 만듦).
- 힌트 문장은 주문 종류에 따라 다릅니다.

| 과제 | 힌트 문장 (예) |
|---|---|
| 계산 (여러 병·맞춤 배수·손님 지정량·생활 소재) | 기력초: 0.6 × 3을 계산해 보세요. / 깃털풀: 0.4 × 4를 계산해 보세요. / 바람 정령의 파편: 0.35 × 4를 계산해 보세요. |
| 손님 지정 기준량 | 기력초: 2 × 0.35를 계산해 보세요. (손님이 정한 양) |
| 지정량 (생활 소재·비교 주문의 나머지 재료) | 계산하지 않아요. 레시피북에서 1병당 양을 확인하고 그대로 넣어요. (새 식을 만들지 않음) |
| 비교 ⑦ | 지난번 식 0.6 × 3과 이번 식 6 × 3을 비교해 보세요. 곱하는 두 수가 각각 몇 배가 되었는지 살펴보세요. |

- 힌트에는 계산 결과, 정답 수량, 단계별 풀이, 정답을 알려 주는 문장을 넣지 않습니다.
- 계량 패널의 힌트 버튼과 단계별(1~3단계) 힌트 카드는 지웠습니다.
- **오답 뒤 ‘계산 과정’ 해설은 그대로**입니다.
- 계량 중에 주문서를 열어 힌트를 보고 닫아도 입력 중인 답·계량 패널·제조 진행이 그대로 남습니다. 힌트는 돈과 진행에 영향이 없습니다.
- 힌트 사용 기록 (`REVEAL_HINT`):
  - 공개하는 순간 아직 답을 내지 않은 학습 과제(계산·비교)만 `hintLevel = 1`이 됩니다.
  - 여러 번 열어도 다시 세지 않습니다(상태가 바뀌지 않음).
  - 이미 답을 낸 문제의 기록은 소급해서 바꾸지 않습니다.
  - 이전 버전의 단계별 힌트 기록(1~3)은 그대로 보존합니다. 학습 기록 화면에는 ‘사용’ 또는 ‘n단계(이전 버전)’로 표시합니다.

### 영업 결과 화면 (`src/components/ClosingScene.tsx`)

- 결과는 네 가지만 보여 줍니다.

| 항목 | 뜻 |
|---|---|
| 오늘 수입 | 이번 영업에서 받은 판매금 합계 (`day.moneyEarned`, 재료 구매로 줄지 않음) |
| 응대한 손님 | 판매한 손님 수 |
| 현재 소지금 | 지금 쓸 수 있는 잔액 (`state.money`, 누적 매출 아님) |
| 잘못 만든 포션 | 틀린 재료 과제가 하나라도 있는 주문의 **병 수 합** |

- ‘잘못 만든 포션’ 예:
  - 3병 주문에서 한 재료만 틀려도 3병, 두 재료가 다 틀려도 3병입니다.
  - 맞춤·특별 주문(1병)은 1병입니다.
  - 정답 재료 수나 틀린 문제 수로 세지 않습니다.
  - 주문마다 저장된 실제 병 수(`order.bottles`)로 계산합니다(`wrongPotionCount`).
- 버튼은 **다음 날 영업**과 **타이틀로** 두 개입니다. ‘재료 해금’ 버튼과 마감 화면의 해금 메뉴(`UnlockMenu.tsx`)는 지웠습니다.
- 닫힌 덧문 배경과 ‘오늘 영업 종료’ 팻말은 그대로입니다.
- 다른 통계는 화면에서만 뺐습니다. 영업 기록(`dayHistory`), 학습 기록, 내보낸 JSON에는 그대로 남습니다(계산 문제 수, 정확·다름, 힌트, 만족도, 복습, 지정량 결과). 새 집계 `potionsMade`·`wrongPotions`도 함께 기록합니다.

### 창구 왼쪽 아래 주문 요약 (`src/components/CounterScene.tsx`)

- **손님 n / 5**와 **정상 판매가 ○G** 두 줄만 남겼습니다. 글자는 약 16~18px로 키우고 상자를 작게 줄였습니다.
- 지운 것: 포션 이름, 병 수·조건, 재료 설명, 주문 번호, 보충 문장.
- 정상 판매가는 품질 감액 전 금액입니다. 실제 지급액은 판매 후 문장(“정상 판매금 ○의 ○% → 달빛 동전 ○개”)에서 따로 보여 줍니다.
- NPC 대사와 제작대 주문서 팝업은 줄이지 않았습니다.

## 2. 제작대 서랍 구매

| 서랍 | 재료 | 처음 상태 | 해금 가격 |
|---|---|---|---|
| 1번째 (맨 왼쪽 위) | 기력초 | 사용 가능 | 무료 |
| 2번째 | 깃털풀 | 잠김 | 70 |
| 3번째 | 바람 정령의 파편 | 잠김 | 110 |
| 4·5번째 | (이전 버전 주문을 마치는 동안만 달빛 이슬·별가루) | — | 팔지 않음 |
| 그 밖 | 빈칸 (가격·버튼 없음) | — | — |

- ‘바람풀’이라는 별도 재료는 없습니다.
- 잠긴 칸:
  - 그 칸 안쪽만 어둡게 하고, 서랍 테두리나 배경 PNG 전체는 덮지 않습니다.
  - 칸 안에 자물쇠·금화·가격과 **잠금 해제** 버튼을 둡니다. 칸 안쪽 전체가 버튼이라 태블릿에서 누르기 쉽습니다.
  - 칸 아래 이름판에 재료 이름표가 있습니다(다른 서랍 이름표와 같은 자리).
- 잔액이 부족하면 버튼이 회색입니다. 눌러도 “달빛 동전이 ○개 더 필요해요. (가격 ○ · 지금 ○)” 안내만 나오고, 돈과 해금 상태는 바뀌지 않습니다.
- 사면 사용 권한이 영구로 생깁니다(재고 구매가 아님).
  - 잠금·어두운 칸·가격이 사라지고 그 칸에 재료 더미가 놓입니다. 바로 클릭·끌기로 쓸 수 있습니다.
  - 사는 순간의 클릭·터치와 0.7초 안에 이어진 클릭은 재료 집기·항아리 조작으로 이어지지 않습니다.
- 구매 차단:
  - 계량 패널이 열려 있으면 화면과 게임 규칙 양쪽에서 막습니다(`activeTask`).
  - 재료를 끄는 중, 막대를 잡고 젓는 중, 병에 담는 중, 팝업이 열려 있을 때는 화면에서 막고 안내합니다.
  - 구매해도 진행 중인 제조 상태는 초기화하지 않습니다.
- 가격과 구매 가능 여부는 게임 규칙(`UNLOCK_INGREDIENT` → `tryUnlock`)이 내부 데이터로 다시 검사합니다. 화면이 보낸 가격은 쓰지 않습니다.
  - 잔액 부족, 이미 해금한 재료, 없는 재료, 이전 버전 재료는 상태를 바꾸지 않습니다.
  - 연달아 눌러도 돈이 한 번만 빠집니다.
- 이번 주문에 필요 없는 해금 재료를 누르거나 항아리에 놓으면 넣지 않고 “이번 주문에는 ○○이 필요 없어요.”라고 짧게 안내합니다. 오답·감액은 없습니다. 선택·끌기·드롭은 기력초와 같은 규칙입니다.

### 신규 재료 그래픽 (`src/components/art/WindArt.tsx`, 코드로 그린 SVG)

- **깃털풀**: 가운데 잎줄기 양쪽으로 가늘고 길게 갈라진 잎 조각이 깃털처럼 퍼진 밝은 연녹색 풀입니다.
  - 서랍 더미는 밑동이 모이고 위로 부채꼴로 퍼집니다.
  - 집었을 때 아이콘은 깃 세 갈래입니다.
- **바람 정령의 파편**: 투명한 청록·하늘색 결정 조각입니다.
  - 세 면의 밝기를 다르게 하고 빛 반사를 넣었습니다.
  - 주변에 흐르는 점선 바람 결(움직임)이 있습니다.
- 기력초(둥근 잎 다발·묶은 끈)와 모양·색이 구분됩니다. 색 원이나 이모지가 아닙니다.

## 3. 바람 걸음 포션과 가격

| 항목 | 값 | 근거 |
|---|---|---|
| 깃털풀 1병당 | **0.4g** (소수 한 자리) | 여러 병 → ① 0.4 × n, 맞춤 배수 → ⑤ 0.4 × 0.○ |
| 바람 정령의 파편 1병당 | **0.35g** (소수 두 자리) | 여러 병 → ② 0.35 × n, 맞춤 배수 → ⑥ 0.35 × 0.○ |
| 여러 병 판매가 | **1병 6** (기력 포션 5) | 계량 문제가 2개라 20% 높게 |
| 특별 주문 판매가 | **24** (기력 포션 20) | 같은 비율 |
| 재료 해금 가격 | **깃털풀 70, 바람 정령의 파편 110 (합 180)** | 아래 표 |

- 기본량은 데이터(`src/data/recipes.ts`)에 고정되어 있고, 출제 때문에 바꾸지 않습니다. 단위는 모두 g입니다.
- 해금 가격 근거는 실제 출제기(`planDay`)로 하루 주문을 2,000번씩 만들어 계산한 기력 포션 하루 정상 판매금 평균입니다.

| | 모두 정답(100%) | 모두 오답(60%) |
|---|---|---|
| 1일차 (①② 소개) | 약 132 | 약 79 |
| 2일차 이후 | 약 110 | 약 66 |

- 이 기준으로 보면:
  - 모두 정답이면 1일차에 깃털풀(70)을 사고, 2일 합계 약 243으로 둘 다(180) 살 수 있습니다(약 1~2일).
  - 모두 오답이어도 2일 합계 약 145, 3일이면 약 211이라 계속 영업하면 살 수 있습니다.
  - 자동 테스트가 이 조건을 다시 계산해 확인합니다.
- 반복 구매 비용은 없습니다.
- 제조 순서:
  1. 재료 선택(순서 자유) → 계량 문제 → 답 확정 → 투입을 두 재료 모두 합니다.
  2. 두 재료를 다 넣은 뒤 젓기 → 병에 담기 → 전달합니다.
  - 두 재료를 다 넣기 전에는 젓기와 완성이 막힙니다.
- 품질: 두 재료 정답 100%, 한 재료 정답 80%, 둘 다 오답 60%입니다. 기력 포션은 기존대로 정답 100%, 오답 60%입니다. 힌트·‘네?’는 감액하지 않습니다.
- 하루 계산 문제 수는 실제 과제 수로 셉니다(기력 포션 주문 1문제, 바람 걸음 포션 여러 병·맞춤 주문 2문제).

### 새 레시피 해금 안내 (`src/components/RecipeUnlockNotice.tsx`)

- 두 번째 재료까지 사서 바람 걸음 포션이 처음 해금되면 한 번 뜹니다.
- 구성:
  - ‘새 레시피 해금’ 제목과 포션 이름·그림
  - **[깃털풀] 0.4g + [바람 정령의 파편] 0.35g = [바람 걸음 포션]**
  - ‘1병 기준’ 표시
  - “두 재료를 계량해 넣고 저으면 완성!”과 “다음 영업부터 주문이 들어와요.”
  - 확인 버튼
- 물·기본 용액은 표시하지 않습니다.
- 구매·해금은 게임 상태에 먼저 저장되고, 안내 팝업은 그것을 보여 주기만 합니다.
  - 확인 전에 새로고침해도 돈이 다시 빠지지 않고, 안내는 다시 뜹니다(`recipeNotices`에 저장).
  - 확인하면 다시 뜨지 않습니다.

### 해금 후 주문 반영

- 오늘 이미 정해진 주문 5건(포션·재료·숫자·보상·진행)은 구매 전후가 같습니다.
- 다음 영업의 주문을 만들 때부터 바람 걸음 포션이 들어갑니다.
  - 새로 해금된 레시피는 `featuredRecipes`에 저장됩니다.
  - 다음 영업에서 현재 소개된 유형으로 낼 수 있는 그 레시피의 여러 병·맞춤 배수 주문을 **최소 1건** 넣고, 목록에서 지웁니다.
- 잠긴 레시피와 재료 하나만 해금된 레시피는 출제하지 않습니다.
- 복습 주문, 최근 문제 덱, 특별 주문 제한은 그대로입니다.

## 4. 저장 호환 (저장 버전 4 → 5)

| 버전 4 저장 | 버전 5에서 |
