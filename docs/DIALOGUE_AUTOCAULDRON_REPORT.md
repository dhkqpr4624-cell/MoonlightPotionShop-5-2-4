## 1. 주문 대사 개선

### 1-1. 문제은행 개정판 적용 (180문항)

- `scripts/convert-question-bank.ts`의 원본을 개정판 TXT로 바꾸고 `src/data/questionBank.ts`를 다시 만들었습니다. 이전 원본은 기록용으로 남겨 두었고 게임에는 쓰지 않습니다.
- **기존 ID 기준 갱신, 중복 없음.** 180문항 모두 ID·난이도·곱셈 유형·포션·지정 재료·a·b·정답·병 수가 직전 데이터와 **똑같습니다.** 대사·‘네?’·힌트·해설 문구만 바뀌었습니다.
  - 변환기가 직전 데이터와 비교합니다(`compareWithPrevious`).
  - 테스트는 직전 값 스냅숏(`tests/fixtures/questionbank-values-v0.8.json`)과 비교합니다.
- 변환기에 **주문 대사 검사**를 더했습니다. 하나라도 어기면 변환이 실패합니다. 개정판은 오류 0건입니다.
  - 들어가야 하는 것:
    - 포션 이름, 지정 재료 이름, 지정 양(`a g`)
    - 병당 주문은 `N병`과 `씩`, 배수 주문은 `한 병`과 `b배`
    - 다른 재료가 있는 배수 주문은 ‘다른/나머지 재료’ 처리, 즉 그 재료만 바뀐다는 말
  - 없어야 하는 것:
    - 계산 질문 끝맺음(`몇 g`·`총량`·`전체 양`·`모두 합해`·`얼마`·물음표)
    - 대사와 ‘네?’ 속의 식(`×`·`=`)과 정답
  - ‘네?’(재설명)와 원래 주문의 수가 서로 맞아야 합니다.
- 개정판 원문에서 바로잡은 글자는 **243곳**입니다. 숫자·식·정답·문장 구성은 그대로입니다. 전체 목록은 [`question-bank/CONVERSION_REPORT.md`](question-bank/CONVERSION_REPORT.md)에 있습니다.

  | 바로잡은 것 | 예 | 곳 |
  |---|---|---|
  | 포션·재료 이름 뒤 조사 | `산호빛 해독제은` → `산호빛 해독제는`, `거인의 활력수은` → `거인의 활력수는` | ‘네?’ 24 · 주문 대사 일부 |
  | 숫자 뒤 을/를 | `÷ 10를` → `÷ 10을`, `4을` → `4를` | 해설 180 · 주문 대사 일부 |
  | 병 수 명시 | `일행 3명에게 바람 걸음 포션을 한 병씩 나누려 하오.` → `… 한 병씩, 모두 3병 나누려 하오.` | 주문 대사 15 |

  항목별로는 주문 대사 39곳, ‘네?’ 24곳, 해설 180곳, 힌트 0곳입니다.
- 문제은행 주문의 ‘네?’에는 다른 재료가 있는 레시피일 때 그 재료 처리 문장을 덧붙입니다. 개정판 재설명에 이미 있으면 덧붙이지 않습니다.
- 주문서 메모의 특별 조건에는 “○○의 b배, **이 재료만**”이라고 적습니다.

### 1-2. 생성 주문 템플릿 · NPC 말투 · 기다리는 말

`src/data/dialogues.ts`의 네 말투(하오·합쇼·하게·기사)와 `src/game/orderFactory.ts`를 고쳤습니다.

| 주문 종류 | 바뀐 점 |
|---|---|
| 여러 병(multiBottle) | ‘네?’가 “기력 포션 6병이오. …”처럼 포션·병 수로 시작 |
| 맞춤 배수(customMultiplier) | “**모든 재료**를 기본 레시피의 0.5배로…” — 레시피 전체가 바뀐다는 것을 밝힘 |
| 손님 지정량(customAmount) | 1병당/기준 배수 ‘네?’가 포션·병 수로 시작 |
| 생활 소재(lifeItem) | ‘네?’ 맨 앞에 “바람 걸음 포션 한 병이오.”, 다른 재료는 레시피북 1병 기본량이라는 문장 유지 |
| 비교(⑦ pointShift) | 원래 주문이 “거인의 활력수 한 병을 부탁하오. 지난번에는 기력초를 0.8의 6배인 4.8g 넣었소. 이번에는 기력초를 0.08의 6배만큼 넣어 주시오. …”처럼 포션·한 병으로 시작하고, 다른 재료 처리 문장을 덧붙임. ‘네?’도 같은 수(지난번 양 포함) |
| 기다리는 동안 창구 | 분위기 말(“서두를 것 없소. 창가에서 기다리겠소.”) 아래에 “기력 포션 한 병, 잘 부탁하오.”처럼 **포션·병 수**를 다시 말함 (`reminderLine`) |

- 인사(분위기 말)는 늘 원래 주문과 함께 나옵니다. 분위기 말이 주문을 대신하지 않습니다.
- 식은 주문서 **힌트**에만, 풀이 단계와 정답은 **오답 뒤 해설**에만 나옵니다. 대사·‘네?’·메모에는 없습니다.

### 1-3. 저장된 주문 대사

- 이어하기 때 문제은행 주문의 대사·‘네?’·메모를 바꾸는 조건은 둘입니다.
  - 저장된 **문항 ID가 있고**
  - 그 주문의 지정 재료·a·b·레시피가 문항과 **똑같을 때**
- 바꿀 때도 인사·기다림·반응 말과 주문 수치·진행·보상은 그대로입니다.
- 조건이 다르면 바꾸지 않고, 다른 문항으로 바꿔 끼우지도 않습니다.
- 저장 파일의 인수를 손으로 고친 경우는 원래부터 저장 검사에서 걸러집니다.

## 2. 마녀의 자동 가마솥 = 즉시 완성

| 항목 | 동작 |
|---|---|
| 적용 조건 | **가지고 있으면 늘 적용.** 상점의 켜기/끄기 스위치를 없애고 ‘항상 적용’ 표시. 예전 저장의 ‘꺼짐’도 무시 |
| 설명 | “재료를 모두 넣으면 포션이 바로 완성됩니다.” (이어서: 계량 문제와 넣기는 그대로 직접 하고, 젓기와 병에 담기를 건너뛰어요. 완성한 포션은 창구에서 직접 전달해요.) |
| 완성 시점 | 마지막 재료를 `ADD_TO_CAULDRON`으로 넣는 순간 **reducer 안에서** 병에 담긴 상태(`bottled`, 젓기 100)로. UI 타이머(이전 자동 젓기)는 없앰 |
| 그대로인 것 | 재료마다 계량 문제, 채점, 오답 해설, 넣기, 오답에 따른 **품질·판매금 감점**, 복습 후보 |
| 막는 것 | 하나라도 안 넣었으면 완성 안 됨. 재료를 자동으로 넣거나 오답을 정답으로 바꾸지 않음 |
| 전달·지급 | 완성 때는 돈이 바뀌지 않음. 학생이 창구에서 직접 전달할 때 한 번만 지급(기존 `paidOrderIds` 규칙) |
| 중복 방지 | 같은 넣기·병 담기·젓기 입력을 반복하거나 새로고침·불러오기를 해도 이미 `bottled`라 다시 완성하지 않음 |
| 젓는 중에 구매 | 재료를 다 넣고 젓는 중에 사면 그 주문도 바로 완성(`BUY_ITEM`에서 같은 함수) |
| 없을 때 | 기존과 똑같이 손으로 젓고 ‘병에 담기’ |

## 5. 실행하지 못한 것

- **진짜 `npm install`·`vite build`·`tsc -p tsconfig.json`**: 이 작업 환경은 npm 레지스트리에 접속할 수 없어 의존성을 설치하지 못했습니다.
  - 대신 esbuild로 같은 설정(base `/MoonlightPotionShop-5-2-4/`, `public/` 복사)의 정적 빌드를 만들어 브라우저 점검을 했습니다.
  - 타입 검사는 React 타입을 최소한으로 흉내 낸 파일로 `strict` 검사를 했습니다.
  - 실제 저장소의 GitHub Actions(`deploy.yml`)가 `npm ci && npm run build`를 하므로, 올린 뒤 Actions 결과를 한 번 확인해 주세요.
- **실제 태블릿·휴대폰**: Chromium 기기 흉내만 했습니다. 실제 터치 기기 확인은 하지 못했습니다.
- **GitHub 쓰기·배포**: 요청대로 하지 않았습니다.

## 6. 남은 참고 사항

- 개정판 TXT의 **기력 포션**(재료 한 가지) 문항 12개 가운데 일부는 ‘네?’에 “다른 재료는 레시피대로…” 문장이 있습니다.
  - 기력 포션에는 계량할 다른 재료가 없습니다. 이 문장은 자동으로 담기는 기본 용액을 가리키는 말로 읽혀 해가 없으므로 원문대로 두었습니다.
  - 지우려면 TXT에서 고친 뒤 `node scripts/convert-question-bank.ts`를 실행하면 됩니다.
- 문제은행 대사는 원문(하오체)이라 토끼·표범 손님은 인사·반응만 자기 말투입니다(기존과 같음). 기다리는 말 다시 말하기는 손님 말투를 따릅니다.
- 상품 이름은 기존 그대로 “마녀의 자동 솥”입니다.
