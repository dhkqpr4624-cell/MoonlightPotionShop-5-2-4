### 젓기: 버튼 삭제, 직접 조작만

- 화면 어디에도 젓기 버튼이 없습니다(`data-testid="stir"`·‘젓기’ 버튼 0개를 자동 확인).
- 안내 문구 “막대를 잡고 움직여 포션을 저어 주세요.”, 손 모양 표시(잡기 전), 작은 진행 막대와 %.
- 입력 계산은 화면과 분리한 `src/game/stirInput.ts`:
  - 솥 액체 타원 기준으로 정규화 → 화면 크기와 무관하게 비슷한 손 움직임이 필요
  - 진행도 = 막대 끝이 **움직인 거리** × 14 (프레임 수와 무관). 왕복·원 그리기 모두 인정
  - 0.01 미만 떨림 무시 → 가만히 누르기·단순 클릭은 0
  - 한 번의 이동은 0.35까지만 인정 → 한 번에 크게 튀어도 완료되지 않음(약 +5)
  - 막대 끝은 솥 안(반지름 0.82)으로 제한, 손이 솥 밖으로 나가도 막대는 가장자리
  - 한 포인터만 인정(두 번째 손가락 무시)
- 화면 쪽(`WorkbenchScene.tsx`): Pointer Events + `setPointerCapture`, 솥 영역만 `touch-action: none`(패널은 스크롤됨), `pointerup`·`pointercancel`·`lostpointercapture`·창 `blur`·화면 숨김·화면 이탈·젓기 단계 종료에서 잡기 해제. 막대·소용돌이는 ref로 직접 움직여 드래그 중 전체 다시 그리기를 피했습니다. 진행도는 3단계와 같은 `STIR` 액션(한 번 최대 25)으로 저장되므로 놓아도 남고, 새로고침해도 복구됩니다. 두 재료를 넣기 전에는 리듀서와 화면 모두 막습니다. 키보드는 솥에 초점 → ←→.
- 리듀서에서 쓰이지 않게 된 `STIR_BUTTON_STEP` 상수만 지웠습니다(규칙 변화 없음).

### 연출

손님 등장(옆에서 걸어 들어옴)·퇴장(인사하며 나감), 재료 집기(들어 올림·‘집음’ 표시), 끌기 그림자, 솥 놓을 곳 강조(‘여기에 놓기’), 액체 붓기(병 기울임 + 물줄기)·가루 붓기(입자), 젓기(막대·소용돌이·물결), 완성 빛, 병 담기, 판매(동전 +n), 품질 반응(만족: 깡충, 아쉬움: 끄덕, 불만족: 살짝 가라앉음), 덧문 열기·닫기.
- 판매금·재료·일차는 버튼을 누르는 순간 리듀서가 처리하고 연출 끝을 기다리지 않습니다. 연출은 ‘이번 화면에서 상태가 바뀐 순간’에만 재생하므로 새로고침하면 다시 재생되지 않습니다.
- 반응 연출을 손님 그림 안쪽에만 걸어, 반응이 끝난 뒤 등장 연출이 다시 재생되던 문제를 고쳤습니다(검증 중 발견).
- `prefers-reduced-motion`이면 모든 애니메이션을 사실상 0초로 줄입니다. 강한 깜빡임·무한 입자 생성은 없습니다(입자는 정해진 개수의 SVG 요소).

### 효과음 (제작 방식: Web Audio 실시간 합성)

음원 파일·외부 음원·배경음악 없음. `src/audio/sfx.ts`가 사인·삼각파와 걸러 낸 잡음으로 짧은 소리를 만듭니다.
버튼, 재료 집기, 놓기, 액체 붓기, 가루 붓기, 젓기(잡고 움직이는 동안만, 빠르기에 따라 크기·음색 변화), 젓기 완료, 정확(부드러운 두 음), 다름(낮고 짧은 두 음), 병 담기, 판매, 덧문 열기·닫기, 페이지 넘김.
- 첫 클릭·터치·키 입력 전에는 AudioContext를 만들지 않습니다. 생성 실패·미지원이어도 모든 함수가 조용히 넘어갑니다.
- 같은 소리는 70ms 안에 다시 내지 않아 과하게 겹치지 않습니다.
- 소리 설정(켜기·끄기, 음량 0~100%)은 오른쪽 위 ‘소리’ 단추. `moonlight-potion-shop/settings`에 `{version:1, sound:{enabled, volume}}`로 따로 저장. 없거나 망가지면 켜짐·60%.

### 화면·반응형

- 창구: 손님 가운데, 아래 카운터(왼쪽 주문서 / 가운데 받침 / 오른쪽 버튼 고정 위치). 대사창은 크림색 종이 + 이름표로 배경과 구분되고 얼굴을 가리지 않습니다.
- 제조대: 가운데 큰 솥, 아래 나무 작업대 위 재료 그릇, 왼쪽 주문 메모·레시피북, 오른쪽 계량·힌트·해설(같은 자리, 스크롤). ‘병에 담기’는 제조대 아래쪽에 붙어 있어 화면이 낮아도 가려지지 않습니다.
- 1366×768, 1180×820, 1024×768(태블릿 가로), 768×1024(태블릿 세로)에서 가로 스크롤 없음·주요 버튼 화면 안·솥과 재료 겹침 없음·재료 터치 영역 56px 이상을 자동 확인.
- 글꼴: 시스템 한글 글꼴(Pretendard/Apple SD Gothic Neo/Malgun Gothic/Noto Sans KR …) 순서로 대체, 웹폰트 다운로드 없음.

### 저장 호환

- 게임 저장 형식은 **바뀌지 않았습니다**(v3, 키 `moonlight-potion-shop/save`). 3단계 저장(젓기 진행 중 포함)이 그대로 열립니다. 2단계·1단계 저장은 3단계와 같은 방식으로 옮겨지고 원본은 백업 키에 남습니다. 저장을 지우거나 자동으로 바꾸지 않습니다.
- 새로 생긴 값은 소리 설정뿐이고 게임 저장과 다른 키에 저장되므로 내보내기·가져오기 파일 형식도 그대로입니다.

## 4. 검증 결과

### 실행 환경의 제한 (중요)

이 작업 환경은 조직 정책으로 npm 저장소 접근이 차단되어 있습니다(`npm view vite` → HTTP 403, 이번에도 확인). 그래서 아래는 **실행하지 못했습니다.**

| 실행하지 못한 것 | 대신 한 것 |
|---|---|
| `npm install` / `npm ci` | — |
| 실제 `npm run typecheck` (TypeScript 5.9 + 실제 `@types/react`) | 이 환경의 TypeScript 6.0.3으로 같은 `tsconfig.json`(strict, noUnused…)을 쓰되, React 타입은 **직접 만든 간이 선언(shim)** 으로 검사 → 오류 0. 실제 `@types/react`와 다를 수 있습니다 |
| 실제 Vite 빌드 (`npm run build`) | 이 환경에 있던 React 19.2 + esbuild로 같은 소스를 `base=/MoonlightPotionShop-5-2-4/`로 번들(**Vite 빌드가 아님**) → 그 결과물로 브라우저 시험 |
| GitHub Actions 실행·배포 | 하지 않음(요청대로 GitHub에는 아무것도 하지 않음) |

### 소리 검증 방식 (정직하게)

소리는 **귀로 직접 들어 보지 않았습니다**(이 환경에는 스피커가 없습니다). 확인한 것은 코드와 이벤트 수준입니다: 브라우저에서 AudioContext 생성 시점(첫 입력 전 0개), 버튼·젓기 완료 때 소리 노드가 시작되는지, 젓기 반복 소리가 잡는 동안 1개만 있고 놓기·취소·화면 이탈 때 멈추는지, 소리를 끄면 노드가 만들어지지 않는지, 새로고침 뒤 지난 소리가 다시 시작되지 않는지. 소리 크기·음색이 교실에 알맞은지는 실제 기기에서 한 번 들어 보시길 권합니다(필요하면 음량을 낮추거나 끄면 됩니다).

타이틀, 창구(주문·‘네?’), 유형 소개, 제조대(재료 전·집기·끌기·젓기 준비·젓는 중·완료), 오답 해설, 판매 반응(아쉬움·불만족), 마감(덧문·팻말), 학습 기록, 소리 설정, 태블릿 가로·세로.

## 5. 남은 제한 사항

- 실제 Vite 빌드와 실제 `@types/react` 타입 검사는 npm 차단으로 이 환경에서 돌리지 못했습니다. GitHub Actions에서 처음 빌드될 때 확인됩니다(실패하면 Actions 로그를 알려 주세요).
- 터치 시험은 Chromium의 터치 이벤트 흉내로 했습니다. 실제 iPad Safari·안드로이드 태블릿에서는 직접 확인하지 못했습니다.
- 자동 시험에서, 손가락을 뗀 뒤 수 밀리초 안에 바로 버튼을 탭하면 브라우저 제스처 판정 때문에 탭이 무시되는 경우가 있었습니다(사람 속도인 0.4초 뒤에는 항상 정상). 실제 사용에서는 문제가 되지 않을 것으로 보지만, 태블릿에서 ‘병에 담기’가 가끔 안 눌린다면 알려 주세요.
- 그림은 코드로 그린 SVG라 전문 원화보다 단순합니다. 교체 위치는 README ‘그림 교체하기’에 정리했습니다.
- 효과음은 합성음이며 배경음악은 없습니다.
