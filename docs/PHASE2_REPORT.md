## 1. Phase 1 분석 요약

| 항목 | Phase 1 상태 | Phase 2에서 |

## 2. 구현 내용

### 하루 영업
- 하루 = 손님 5명. 상단에 `밤 N일차 · 손님 k / 5` 표시.
- 주문 5건(ID `order-<번호>`, 전체 게임에서 고유)은 영업 시작 때 정해져 저장 → 새로고침해도 같은 주문.
- 다섯 번째 손님 판매 후에는 ‘다음 손님’ 대신 ‘영업 마감’ 버튼만 나옴(리듀서도 여섯 번째 손님을 막음).

### 한 번만 일어나야 하는 행동 (리듀서에서 보장)
| 행동 | 함께 보내는 값 | 처리 조건 |
|---|---|---|
| `DELIVER` | `orderId` | 현재 주문 ID와 같고, 상태가 `bottled`, `paidOrderIds`에 없을 때만 |
| `NEXT_CUSTOMER` | `fromOrderId` | 현재 주문 ID와 같고 `paid`이며 마지막 손님이 아닐 때만 |
| `CLOSE_DAY` | `dayNumber` | 영업 중, 같은 일차, 마지막 손님 `paid`일 때만. 결과 기록은 일차당 1개 |
| `NEXT_DAY` | `fromDay` | 마감 상태이고 같은 일차일 때만 → 일차는 한 번만 증가 |

화면에서도 겹 클릭을 막음: 전달 직후(동전 연출 1.6초) ‘다음 손님/영업 마감’ 잠금, 다음 손님 등장(0.8초) 중 ‘주문 받기’ 잠금, 덧문 연출 중 모든 버튼 잠금.

### 영업 마감 화면과 덧문
- ‘영업 마감’ → 손님 퇴장 → 창구 덧문이 좌우에서 닫힘 → ‘오늘 영업 종료’ 표지판 → 결과 카드(약 1.7초).
- 배경은 닫힌 덧문, 양옆 등불은 계속 은은하게 빛남.
- 표시: 영업 일차, 응대한 손님, 판매한 포션 병 수, 오늘 판매금, 현재 소지금, 전체 문제, 첫 시도에 맞힘, 다시 계산해서 해결, 힌트를 사용한 문제 + 격려 문장. 꾸중·속도 비교 없음.
- ‘다음 날 영업’ → 일차 +1, 새 주문 5건 → 덧문이 열리고 첫 손님 등장. ‘타이틀로’로 나가도 덧문은 닫힌 상태 유지.
- **덧문의 열림·닫힘은 저장된 `day.status`(open/closed)가 결정.** 여닫는 애니메이션은 방금 누른 버튼에 대한 화면 효과일 뿐 저장하지 않으므로, 연출 도중 새로고침하면 최종 모습으로 복구되고 지급·일차 증가가 다시 실행되지 않음.
- 그림 교체: `src/data/shopArt.ts`에 덧문·표지판 이미지 경로를 넣으면 코드 그림 대신 사용.

### 집계
- 별도 카운터 없이 저장된 재료 과제(`status`, `firstCorrect`, `hintLevel`)에서 매번 계산(`game/daySummary.ts`) → 재시도·새로고침·중복 클릭으로 숫자가 어긋나지 않음.
- 재료 1개 = 문제 1개, 첫 시도 정답과 수정 성공 구분, 힌트는 문제당 1회(정답 제출 전에 본 것 포함).

### 저장·이어하기 (버전 2)
저장 항목: 저장 버전, 소지금, 영업 일차, 영업 상태, 오늘의 주문 5건(주문별 상태·재료 진행·보상 지급 여부), 현재 손님 순서, 선택한 재료, 입력 중인 답, 안내 메시지, 판매금 지급 기록, 학습 기록(문제 ID·일차·손님 순서 포함), 오늘 판매금, 지난 영업 결과, 누적 통계, 문제 덱.
새로고침하면 저장된 화면 그대로 복구(Phase 1은 항상 타이틀로 갔음).

### Phase 1 저장 마이그레이션
README ‘Phase 1 저장 데이터 옮기기’ 표 참고. 요약: 돈·통계·지급 기록·학습 기록 보존(기록은 일차 0으로 표시), 판매 전 진행 중 주문은 1일차 첫 손님으로 이어가기, 원본은 `moonlight-potion-shop/backup-v1`에 보관.

### 손상·미지원 저장
덮어쓰지 않고 타이틀에 안내(이유 목록) + 자동 저장 중지. 선택지: 읽지 못한 저장 내려받기 / 저장 파일 가져오기 / 확인 후 지우고 새로 시작.

### 내보내기·가져오기
타이틀 → ‘💾 저장·기록 관리’. 저장 데이터 내보내기, 저장 데이터 가져오기(검사 → 오류면 현재 저장 유지 / 정상이면 비교 확인 창 → 바꾸기), 학습 결과 내보내기(개인 식별 정보 없음).

### 발견·수정한 버그
1. **다음 손님 더블클릭 시 다음 손님의 주문까지 받아 버림**: 두 번째 클릭이 같은 자리에 새로 나타난 ‘주문 받기’를 누름(브라우저 테스트에서 간헐적으로 발견). → 다음 손님 등장 중 0.8초 동안 ‘주문 받기’를 잠그고 등장 연출 추가.
2. Phase 1은 저장이 조금이라도 이상하면 **조용히 새 게임으로 덮어쓸 수 있었음** → 오류 안내 + 저장 중지로 변경.
3. Phase 1 저장 검사가 얕아 조작된 값(예: 레시피 기본량·정답 변경, 지급 기록 누락)도 통과했음 → 주문·레시피·지급 일관성까지 검사.

## 5. 검증 결과

### 실행 환경의 제한 (중요)
이 작업 환경은 npm 저장소(registry.npmjs.org) 접근이 조직 정책으로 차단되어 있습니다(HTTP 403). 따라서 아래는 **실행하지 못했습니다.**

| 미실행 | 이유 | 대신 한 것 |
|---|---|---|
| `npm ci` / `npm install` | 패키지 다운로드 불가 | — |
| 실제 **Vite production build** (`npm run build`) | Vite 설치 불가 | 이 환경에 있던 React 19.2 + esbuild 0.27로 같은 소스를 번들(아래) |
| 실제 `@types/react`로 하는 타입 검사 | 타입 패키지 설치 불가 | TypeScript 6.0 strict 검사: 계산·규칙·저장 코드는 실제 타입으로, 화면 코드는 간이 React 타입 정의로 |
| `package-lock.json` 생성 | 설치 불가 | 만들지 않음(조작하지 않음). workflow는 lock 파일이 없으면 `npm install`, 있으면 `npm ci` |

**GitHub Actions에서 처음 실행될 때가 실제 Vite 빌드입니다.** 배포 후 Actions 탭에서 build·deploy가 초록색인지 확인해 주세요.
