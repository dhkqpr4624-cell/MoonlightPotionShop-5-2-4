## 1. 문제은행 연결

**변환·검증** (`scripts/convert-question-bank.ts`, 결과 `src/data/questionBank.ts`, 자세한 표는 `docs/question-bank/CONVERSION_REPORT.md`)

| 검사 | 결과 |
|---|---|
| 문항 수 / ID 중복 / 필수 필드 16개 | 180 / 0 / 모두 있음 |
| 난이도 × 곱셈 유형 | 하·중·상 각 60, 각 유형 20 (9칸 모두 20) |
| 정답 재계산 (문자열 십진 정수 연산, 부동소수점 없음) | **180/180 일치, 불일치 0건** (원문 정답을 고치거나 버린 문항 없음) |
| 인수 소수 자릿수 / 정답 소수 자릿수 | 모두 2자리 이하 / 4자리 이하 |
| 포션·재료 이름 → 기존 ID | 15쌍 모두 연결, 새 재료 0 (바람 정령의 파편 = `windShard`) |
| 바로잡은 글자 | 힌트 104곳·해설 69곳의 숫자 뒤 조사 ‘을’→‘를’(예: `4을`→`4를`)만. 숫자·식·정답 그대로. 목록은 변환 보고에 |

**주문으로 만들기** (주문 종류 `bank`, 문항 하나 = 재료 하나의 계산 과제)

| 곱셈 유형 | 주문 모양 | 지정 재료 | 다른 재료 | 판매가 |
|---|---|---|---|---|
| 소수×자연수 | 여러 병 (병 수 = b) | 손님이 정한 1병당 양 × 병 수 | 레시피 1병당 양 × 병 수 (계산 과제) | 1병 판매가 × 병 수, 9병 값까지 |
| 자연수×소수, 소수×소수 | 한 병의 배수 | 손님이 알려 준 기준량 × 배수 | 레시피 1병 기본량 그대로 (지정량 계량) | 특별 주문 판매가 |

- 모든 재료를 계량·투입해야 젓기·병 담기가 됩니다. 문항 숫자를 레시피에 맞추려고 바꾸지 않습니다.
- 손님 대사 = `question`, ‘네?’ = `clarification` + 다른 재료 안내, 주문서 메모 = ‘특별 조건’과 ‘기본 조건’을 나눔(식·정답 없음),
  주문서 힌트 = `hint`(식만), 오답 뒤 계량 패널 해설 = `explanation`(①~④). 모두 문항 ID(`bankId`)로 연결해 저장합니다.
- 정답 판정은 동치 소수 인정(0.4 = 0.40, 10 = 10.0). 입력은 8칸까지라 0.1125 같은 네 자리 소수도 넣을 수 있습니다.
- 학습 유형: 소수×자연수 → ①②, 자연수×소수 → ③④, 소수×소수 → ⑤⑥. 소수 두 자리 × 소수 두 자리 20문항은 ⑥으로 묶었습니다.
- 대량 주문(최대 24병) 판매가를 그대로 곱하면 한 주문이 하루 수입보다 커져 경제가 흔들리므로 9병 값까지만 받습니다(대량 할인).

**출제 규칙** (`src/game/questionBank.ts`, `orderFactory.planDay`)

- 후보: 레시피의 **모든 필수 재료**를 해금한 포션 + 지금까지 소개된 학습 유형. TXT의 `required_ingredients`만으로 판단하지 않습니다.
- 난이도: 1~5일차 하 100% / 6~10일차 하 70·중 30 / 11~20일차 하 30·중 60·상 10 / 21일차~ 하 20·중 50·상 30.
  고른 난이도의 후보가 없으면 그 기간에 허용된(비율 > 0) 다른 난이도에서 고릅니다. 허용 밖 난이도·잠긴 재료·소개 전 유형은 쓰지 않습니다.
- 덱: 아직 안 낸 문항부터, 모두 냈으면 가장 오래전에 낸 문항부터(`decks.bank`에 낸 순서 저장). 같은 날 같은 문항·같은 식(생성기·복습 포함)은 피합니다.
- 일반 주문 자리는 문제은행이 먼저, 후보가 없을 때만 기존 생성기. 복습·생활 소재·비교(⑦) 주문, 새 유형 소개·새 레시피 첫 주문 조건, 3재료 하루 2건 제한은 그대로 지킵니다.
- 문제은행 대사가 하오체라 문제은행 주문은 가능하면 여우·늑대 손님에게 맡깁니다(그날 손님 구성은 그대로, 순서만 바꿈).
- 하루 주문·문항 ID·인수·대사·해설은 주문에 저장되어 새로고침해도 같습니다. 진행 중이던 날은 그대로, 문제은행은 다음 영업부터.

**후보 부족과 대체 비율** (섞임 75% 플레이 모의 영업 60회, `scripts/balance30.ts`의 `simulate`)

| 기간 | 문제은행 | 생성기로 대체(후보 부족) | 그 밖(복습·생활·비교·튜토리얼) | 문제은행 하/중/상 |

**30일 균형** (200회 모의 영업 중앙값, 새 레시피 8종이 모두 열리는 날)

|---|---|---|

| 섞임 75% | **32일 (32~33)** | 30일 |

## 2. 제작대 간소화

- 위쪽 밝은 전폭 띠를 없앴습니다. 포션 이름·병 수 제목, 긴 조작 안내, 재료 상태 알약, 젓기·병 담기 상태, 일차·손님 순서, 상점 버튼도 함께 뺐습니다.
- 상시 UI 넷: **처음 화면 · 소리**(왼쪽 아래), **달빛 동전 · 창구 보기**(오른쪽 아래). 제작대 그림 아래쪽 빈 나무판(그림 좌표 y 884~936) 위라 서랍·책·주문서를 가리지 않습니다.
- 상점은 창구와 마감 화면의 상단 상태 UI에서 엽니다.
- 그대로 둔 것: 젓기 진행 막대(저을 때만), ‘병에 담기’·‘창구로 가져가기’(돌판 위), 계량 패널, 잠긴 서랍의 자물쇠·가격·잠금 해제, 안경의 재료 강조.
- 서랍의 ‘다음 목표’ 글자·배지·테두리와 레시피북의 ‘다음 목표’ 줄을 없앴습니다.
- 계량 패널 높이를 줄여(그림 좌표 14~872) 아래쪽 상시 UI와 겹치지 않게 했습니다.

## 3. 타이틀·새로 시작·이어하기

- 타이틀 그림을 무대 전체에 비율 그대로(contain) 보여 줍니다. 그림에 제목·부제가 있어 HTML 제목은 넣지 않았습니다.
- 주 버튼 두 개는 오른쪽 아래 마을 자리(무대 x 1012~1264, y 452~)에 HTML로 둡니다. 제목 간판·가운데 상점·부제와 겹치지 않는 것을 자동 검사했습니다.
- 버튼은 나무·청록 바탕에 황동 테두리이고 높이 62px입니다. 보조 버튼(학습 기록·저장·기록 관리·소리)은 왼쪽 아래에 높이 40px로 작게 둡니다.
- 접속하거나 새로고침하면 늘 타이틀입니다. 화면만 바꾸고 저장된 장면(`scene`)은 바꾸지 않습니다.
- **이어하기**: 저장이 없거나 읽을 수 없으면 비활성입니다. 손님 주문, 계량 중 입력값, 오답 해설, 젓기 40%, 병에 담은 뒤, 전달 뒤, 영업 마감을 모두 복구하는 것을 확인했습니다. 지급은 다시 하지 않습니다.
- **새로 시작하기**: 진행이 있으면 교체 확인 창이 뜹니다. 취소하면 저장이 그대로이고(바이트 비교로 확인), 확인하면 처음 상태와 튜토리얼로 시작합니다. 소리 설정은 유지하고, 연달아 눌러도 한 번만 시작합니다.
- 손상된 저장: 기존 보호 방식(덮어쓰지 않고 자동 저장 멈춤, 원본 내려받기, 가져오기, 새로 시작) 그대로입니다.

## 4. 첫 주문 튜토리얼

- 새로 시작한 게임의 첫 손님은 여우, 주문은 기력 포션 2병(기력초 0.6g × 2, 정답 1.2g)으로 정해 둡니다(`TUTORIAL_ORDER`). 다른 재료와 특별 주문은 쓰지 않습니다.
- 단계는 게임 상태에서 계산합니다(`game/tutorial.ts`):
  1. 소개 카드 확인
  2. 오케이(창구에 나와 있으면 ‘제작대로 가기’)
  3. 주문서 열고 닫기
  4. 레시피북 열고 닫기
  5. 기력초 놓기
  6. 입력·제출
  7. 이 양으로 투입
  8. 젓기
  9. 병에 담기
  10. 창구로
  11. 전달
- 주문서와 레시피북은 ‘열었다 닫음’만 저장합니다(`tutorial.orderViewed`·`recipeViewed`).
- 안내는 실제 요소의 화면 위치를 무대 좌표로 바꿔 금빛 테두리를 그리고, 대상을 가리지 않는 자리에 한두 문장 말풍선을 둡니다. 계량 단계에서는 계량 패널(해설)도 가리지 않습니다. 테두리와 말풍선은 클릭을 막지 않습니다.
- 행동을 해야만 넘어갑니다. 2.5초 기다려도 그대로인 것을 확인했습니다.
- 놓기는 클릭 → 항아리 클릭과 끌어 놓기를 모두 인정하고, 터치 기기에는 ‘눌러 선택하거나 끌어 놓으세요’라고 안내합니다. 주문서·레시피는 키보드(Enter·Esc), 답은 키보드 입력도 인정합니다.
- 정답은 안내에 나오지 않습니다. 오답(1.3)이어도 해설을 보고 그대로 완성하며, 판매금은 품질 규칙대로(60% = 6)입니다. 튜토리얼 보상은 없습니다.
- 건너뛰기: 주문은 그대로 두고 안내만 끝냅니다(`skipped`). 다시 이어해도 나오지 않습니다.
- 새로고침·처음 화면 → 이어하기 뒤 같은 단계부터 다시 안내합니다. 이전 저장(`tutorial: null`)에는 시작하지 않습니다.

## 5. 화면 배율 (기준 무대)

- `Stage.tsx`: 타이틀·창구·제작대·마감과 그 위의 책 팝업·계량 패널·상점·미리보기·안내 창·튜토리얼을 모두 **1280×720 무대 하나**에 그린 뒤, 사용할 수 있는 화면에 통째로 맞춥니다.
  - 사용할 수 있는 화면 = 안전 영역을 뺀 창 크기입니다. ResizeObserver, 회전, visualViewport(주소창)를 따라갑니다.
  - 가로·세로 같은 배율(contain)이고, 비율이 다르면 바깥은 단색 여백입니다. 그림을 자르지 않고, 기기마다 재배치하지 않습니다.
  - 장면 안을 바꾸던 화면 너비 미디어 쿼리와 `vw`·`vh` 크기를 없앴습니다. 학습 기록 화면만 일반 문서처럼 스크롤합니다.
- 포인터 좌표: `clientToLocal()`이 무대 배율과 여백을 거꾸로 바꿉니다. 재료 끌기·항아리 놓기·직접 젓기·끄는 재료 그림 위치가 모두 이 변환을 씁니다. 잠금 해제 등 일반 버튼은 브라우저가 변환 뒤 위치로 판정합니다.
- 계량 입력은 게임 키패드라서 가상 키보드가 뜨지 않습니다. 입력칸이 가려지지 않고 모바일에서도 탭으로 입력할 수 있습니다.
- 항아리(젓기) 영역은 `touch-action: none`, 책 팝업 안은 스크롤이라 서로 구분됩니다.
- 작은 화면을 세로로 들면 ‘가로로 돌리면 더 크게 보여요’ 안내가 뜹니다. 닫을 수 있고, 세로 플레이는 그대로 됩니다.

**실행하지 못한 것** (작업 환경에서 npm 저장소에 연결할 수 없음, DNS 실패)

- 타입 검사는 실제 `@types/react` 대신 간단한 React 타입 선언으로 했습니다.
- 실제 iPhone·Android 기기, Safari: Chromium의 모바일 에뮬레이션(터치·화면 비율)으로만 확인했습니다.
